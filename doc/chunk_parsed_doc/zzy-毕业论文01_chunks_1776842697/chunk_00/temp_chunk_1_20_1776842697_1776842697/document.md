## 摘 要

软件漏洞检测是软件安全领域的关键问题。传统⽅法在误报控制与跨场景 泛化⽅⾯存在明显不⾜，⽽现有深度学习⽅法在复杂漏洞语义建模、持续学习 能⼒及对数据质量的依赖等⽅⾯仍⾯临瓶颈。围绕上述挑战，针对⼤语⾔模型 驱动的漏洞检测⽅法展开系统研究。

针对复杂漏洞语义难以有效建模的问题，构建了结合静态分析的上下⽂增 强检测⽅法。通过精确提取与漏洞相关的关键上下⽂信息，引导⼤语⾔模型聚 焦于语义关键区域，从⽽在降低计算开销的同时提升检测有效性。在空指针异 常（ Null Pointer Exception, NPE ）任务上的结果表明，该⽅法能够准确识别漏洞 并刻画缺陷传播路径， F1 分数达到 0.934 ，体现出良好的检测能⼒与实⽤性。

针对模型在持续演进过程中易发⽣灾难性遗忘的问题，设计了基于核⼼集 的增量学习机制。利⽤参数变化特征刻画数据语义分布，并结合层次聚类构建 ⾼代表性的核⼼⼦集，在引⼊新知识的同时保持既有能⼒。实验表明，仅使⽤约 20% 的核⼼数据即可获得接近全量训练的性能，同时训练时间从 22 ⼩时降低⾄ 约 12 ⼩时，显著提升了模型更新效率。

针对漏洞数据质量参差不齐对模型性能的制约，构建了基于模型⾏为分析 的数据精炼⽅法。通过识别并剔除有害或低质量样本，实现训练数据的动态优 化。实验结果显⽰，经数据精炼后，在多个开源数据集上的 F1 分数平均提升约 5 个百分点，且在低质量场景下性能增益更为显著。

关键词：软件漏洞检测；⼤语⾔模型；增量学习；数据精炼；程序切⽚

## ABSTRACT

Software vulnerability detection is a fundamental problem in the field of software security. Traditional approaches suffer from high false positive rates and limited crossscenario generalization, while existing deep learning -based methods still face significant challenges in modeling complex vulnerability semantics, supporting continual learning, and handling data quality issues. To address these challenges, a systematic study is conducted on large language model (LLM)-driven vulnerability detection.

Toaddress the difficulty of modeling complex vulnerability semantics, a contextenhanced detection approach integrating static analysis is developed . By precisely extracting vulnerability-relevant contextual information, the method guides the LLM to focus on semantically critical regions, thereby improving detection effectiveness while reducing computational overhead. Experimental results on the Null Pointer Exception (NPE) task demonstrate that the approach can accurately identify vulnerabilities and characterize defect propagation paths, achieving an F1 score of 0.934, indicating strong effectiveness and practical applicability.

To mitigate catastrophic forgetting during continuous model evolution, a core- set-based incremental learning mechanism is designed

. Parameter variation features are leveraged to characterize the semantic distribution of data, and hierarchical clus-

tering is employed to construct a highly representative core subset.

This enables the model to retain previously acquired knowledge while incorporating new information.

Experimental results show that using only approximately 20% of the data achieves per- formance comparable to full-data training, while reducing training time from 22 hours

to approximately 12 hours, significantly improving update efficiency.

To address the impact of heterogeneous data quality on model performance, a data refinement method based on model behavior analysis is proposed

. By iden- tifying and filtering harmful or low-quality samples, the approach enables continuous

optimization of training data.

Experimental results indicate that, after refinement, the

F1 score improves by approximately 5 percentage points on average across multiple open-source datasets, with more pronounced gains observed on low-quality datasets.

## 1.1

## 研究背景与意义

软件漏洞检测在软件安全领域中占据着⾄关重要的地位。随着信息技术的 飞速发展，软件系统已经渗透到社会运⾏的各个⾓落，从⾦融交易、医疗健康到 国防安全、基础设施控制，软件的质量与安全性直接关系到国家安全、经济发展 和社会稳定。软件漏洞作为软件系统中普遍存在的安全隐患，可能被恶意攻击 者利⽤来窃取敏感信息、破坏系统功能或实施其他恶意⾏为，造成难以估量的 经济损失和社会影响。

根据美国国家标准与技术研究院（ NIST ）的统计数据显⽰，软件漏洞的数 量呈逐年上升趋势，仅 2023 年披露的公共漏洞数量就超过了 28000 个，创历史 新⾼。这些漏洞涵盖了缓冲区溢出、空指针解引⽤、资源泄漏、 SQL 注⼊等多种 类型，其中 C/C++ 语⾔编写的系统软件由于直接操作底层内存，更容易出现内 存安全相关的漏洞。因此，如何⾼效、准确地检测软件漏洞，在漏洞被利⽤之前 进⾏修复和缓解，已成为软件安全领域亟待解决的核⼼问题。

传统的软件漏洞检测⽅法主要包括静态分析⼯具、动态分析⼯具以及⼈⼯ 代码审查等。静态分析⼯具如 Cppcheck [1] 、 Clang Static Analyzer [2] 、 Infer [3] 等， 通过预定义的规则模式对源代码进⾏扫描，能够在不执⾏代码的情况下发现潜 在的安全问题。这类⽅法的优点是可以覆盖较⼤的代码规模，但存在明显的局 限性：⼀⽅⾯，基于规则的⽅法需要专家⼿动编写和维护检测规则，随着新漏洞 类型的不断出现，规则库需要持续更新，消耗⼤量⼈⼯成本；另⼀⽅⾯，静态分 析⼯具往往产⽣较⾼的误报率和漏报率，尤其是在处理复杂的跨过程漏洞时效 果不佳。

动态分析⽅法通过实际执⾏或模拟执⾏程序来检测漏洞，包括模糊测试 （ Fuzzing ）、符号执⾏等技术。模糊测试通过向程序输⼊⼤量随机或半随机的 测试数据，观察程序是否出现崩溃、内存泄漏等异常⾏为来发现漏洞。符号执⾏

⼈⼯代码审查是最直接的漏洞检测⽅式，由经验丰富的安全专家对代码进 ⾏逐⾏检查。这种⽅法理论上可以发现各种类型的漏洞，但⾼度依赖审查者的 专业知识与经验，且在⾯对数百万⾏代码的⼤型软件项⽬时效率极低，难以满 ⾜现代软件开发快速迭代的需求。

近年来，随着深度学习技术的快速发展，基于深度学习的软件漏洞检测⽅ 法逐渐受到学术界和⼯业界的⼴泛关注。与传统⽅法相⽐，深度学习模型能够 通过训练⾃动学习代码中的漏洞模式，⽆需⼈⼯设计复杂的检测规则，具有更 强的适应性和泛化能⼒。尤其是⼤语⾔模型（ Large Language Model, LLM ）的出 现，为软件漏洞检测带来了新的机遇。⼤语⾔模型在海量代码语料上进⾏了预 训练，已经学习到了丰富的代码语义知识和编程模式，展现出对代码复杂语义 的强⼤理解能⼒。通过指令微调（ Instruction Tuning ） 、 QLoRA 等⾼效参数微调 技术，将预训练的⼤语⾔模型适配到漏洞检测任务上，可以有效避免从头训练 模型的⾼昂成本，同时获得更好的检测性能。

近期，基于⼤语⾔模型的 AI Agent 技术在代码分析与安全检测领域展现出 显著潜⼒。以 Claude Code 为代表的⼯具能够⾃主调⽤静态分析、符号执⾏、动 态测试等专业化⼯具，形成多⼯具协同的漏洞检测与修复⼯作流，其表现已接近 经验丰富的安全⼯程师。然⽽，此类基于 Agent 的⽅法在实际应⽤中仍⾯临若⼲ 挑战：⾸先，多轮迭代与⼯具调⽤导致 Token 消耗量巨⼤，显著推⾼使⽤成本； 其次，分析过程耗时较长，难以满⾜软件开发快速反馈的需求；再次，主流⽅案 依赖闭源商业模型，存在数据隐私与供应链安全风险。上述因素限制了 Agent 技 术在⼤规模安全检测场景中的普及应⽤。

针对上述问题，探索了⼀条更为⾼效、经济的技术路径：采⽤参数规模适中 的开源⼤语⾔模型，结合轻量级静态分析⼯具，实现⾼精度、低成本的漏洞检 测。核⼼思路在于，充分利⽤静态分析⼯具在代码切⽚与上下⽂限定⽅⾯的精 确性，通过过程间切⽚技术构建能够覆盖完整缺陷传播路径的代码上下⽂，使 模型输⼊尽可能涵盖与缺陷分析相关的全部语义信息；同时，设计结构化的输 出格式，要求模型明确给出从缺陷触发点（ Source ）到缺陷影响点（ Sink ）的完

整数据流路径，⽽⾮仅输出⼆元判定结果。这种设计既使模型能够在完整的缺 陷上下⽂中进⾏推理，提升了检测的准确性和可解释性，⼜使输出结果能够直 接被开发者理解和⽤于漏洞修复，降低了⼈⼯验证成本。

此外，软件漏洞检测技术的实际落地还⾯临两个关键问题。其⼀，软件系统 处于持续演进之中，编程语⾔特性、硬件架构和应⽤场景的变化可能引⼊新的漏 洞类型，检测⼯具需要具备持续学习新知识的能⼒。然⽽，深度学习模型普遍存 在 ' 灾难性遗忘 ' 问题，即在学习新知识时会遗忘旧知识，导致原有检测能⼒下 降。如何在不损害既有性能的前提下实现检测模型的增量更新，是需要解决的重 要问题。其⼆，现有公开漏洞检测数据集普遍存在标注质量低、漏洞类型单⼀、 正负样本不平衡等问题，直接使⽤此类数据训练的模型性能难以满⾜实际需求。 因此，如何从低质量数据中精炼出⾼质量训练样本，提升模型训练效果，同样是 需要深⼊研究的问题。

基于上述分析，围绕基于⼤语⾔模型的软件漏洞检测技术展开系统探索，旨 在构建⼀个⾼效、准确、可持续演进的漏洞检测框架。相关研究得到了企业合作 项⽬的⽀持，为后续应⽤转化奠定了基础。

## 1.2 国内外研究现状

## 1.2.1 基于深度学习的漏洞检测研究现状

基于深度学习的漏洞检测研究可以追溯到 2018 年， Li 等⼈提出的 VulDeePecker [4] 是最早将深度学习应⽤于漏洞检测的代表性⼯作之⼀。该⽅法将代码表 ⽰为数据依赖图（ Data Dependency Graph ） ，利⽤双向 LSTM ⽹络学习代码特征， 能够检测缓冲区溢出和缓冲区读取漏洞。随后， Lin 等⼈提出了跨项⽬的迁移表 ⽰学习⽅法，通过在不同项⽬之间迁移漏洞知识来提⾼检测的泛化能⼒ [5] 。

随着 Transformer 架构的兴起，基于预训练语⾔模型的漏洞检测⽅法逐渐成 为主流。 Choi 等⼈利⽤神经记忆⽹络从原始代码中预测缓冲区溢出漏洞，实现 了端到端的漏洞检测 [6] 。 Devign 是另⼀个具有影响⼒的⼯作，该研究从四个⼤ 型 C 语⾔开源项⽬（ Linux Kernel 、 QEMU 、 Wireshark 、 FFmpeg ）中收集并⼈⼯ 标注了函数级漏洞数据，提出了基于图神经⽹络的漏洞检测⽅法 [7] 。

近年来，研究者开始探索利⽤⼤语⾔模型进⾏漏洞检测。 CodeBERT 、 Graph-

CodeBERT 等代码预训练模型在代码理解任务上展现出强⼤能⼒，为漏洞检测提 供了新的技术路线。这些模型在海量代码语料上进⾏了预训练，学习到了代码的 语法结构、语义信息以及数据流和控制流特征，能够有效捕捉漏洞的深层模式。

## 1.2.2 ⼤语⾔模型在代码任务中的应⽤研究

⼤语⾔模型在代码任务中的应⽤研究是当前的热点⽅向。 StarCoder 、 CodeLlama 、 CodeQwen 等代码专⽤⼤语⾔模型相继发布，在代码⽣成、代码补全、代 码修复等任务上取得了突破性进展。 Lozhkov 等⼈发布的 StarCoder2 模型在多个 代码基准测试中达到了当时的最优⽔平，展现了⼤语⾔模型处理复杂代码任务 的能⼒ [8] 。

在漏洞检测⽅⾯，⼤语⾔模型的优势主要体现在以下⼏个⽅⾯：第⼀，⼤语 ⾔模型能够直接处理原始代码序列，⽆需像⼩模型那样将代码转换为控制流图、 程序依赖图等中间表⽰形式，减少了预处理开销和误差引⼊；第⼆，⼤语⾔模型 参数量⼤，能够捕捉更复杂的代码模式和依赖关系，具有较强的泛化能⼒；第 三，⼤语⾔模型通常⽀持较长的输⼊序列，可以覆盖更完整的代码上下⽂，有利 于检测跨函数、跨模块的复杂漏洞；第四，⼤语⾔模型已经通过预训练学习到了 海量代码知识，微调时只需学习漏洞检测的特定知识，训练效率⾼。

近期，基于⼤语⾔模型的 AI Agent 在代码任务上的进展尤为引⼈注⽬。这 类 Agent 系统不仅能够独⽴理解和分析代码，还能主动调⽤静态分析⼯具（如 Cppcheck 、 Infer ） 、 符号执⾏引擎（如 KLEE ） 、 动态测试框架（如 AFL 、 libFuzzer ） 等专业⼯具进⾏协同分析。通过将复杂任务分解为多个⼦任务、智能编排⼯具 调⽤、并根据中间结果进⾏迭代推理， Agent 系统能够处理传统单⼀⽅法难以应 对的复杂漏洞检测场景。例如，在检测到潜在漏洞后， Agent 可以⾃动调⽤符号 执⾏⼯具验证路径可⾏性，或调⽤动态测试⼯具⽣成复现⽤例，最后综合各类 证据给出漏洞判定和修复建议。这种多⼯具协同的⼯作模式显著提升了漏洞检 测的准确性和可信度，已接近⼈类安全专家的分析能⼒。

## 1.2.3 增量学习与灾难性遗忘问题研究

灾难性遗忘（ Catastrophic Forgetting ）是深度学习模型在持续学习过程中⾯ 临的普遍问题。 Toneva 等⼈通过实证研究发现，深度神经⽹络在学习新数据时 会遗忘之前学习过的样本，导致模型在旧任务上的性能显著下降 [9] 。 Wang 等⼈ 对持续学习进⾏了全⾯综述，将现有⽅法分为基于回放、基于正则化和基于参 数隔离三⼤类 [10] 。

基于回放（ Replay ）的⽅法通过保留⼀部分旧数据或使⽤⽣成模型合成旧数 据的代表样本，在训练新任务时同时训练旧数据，从⽽缓解遗忘问题。 Aljundi 等⼈提出了基于梯度的样本选择⽅法，通过计算样本梯度之间的余弦相似度来 选择代表性样本 [11] 。 Tiwari 等⼈提出了梯度核⼼集（ Gradient Coreset ）⽅法，将 核⼼集选择问题转化为优化问题，在视觉效果和效率之间取得平衡 [12] 。

然⽽，现有的增量学习⽅法在处理⼤语⾔模型时⾯临新的挑战。⼤语⾔模型 参数量巨⼤，存储每个样本的梯度变化计算开销和存储开销都⾮常⾼，难以直 接应⽤于海量参数的模型。此外，如何确定核⼼集的⼤⼩、如何平衡新旧数据的 ⽐例等问题也缺乏系统的研究。

## 1.2.4

## 数据质量与数据精炼研究

数据质量对深度学习模型的性能有着决定性影响。 Jain 等⼈对 C/C++ 漏洞 检测数据集进⾏了系统性评估，发现现有数据集普遍存在标注质量低、漏洞类 型单⼀、正负样本不平衡等问题 [13] 。这些问题直接影响了模型的训练效果和泛 化能⼒。

数据精炼（ Data Refinement ）是提升数据质量的重要技术⼿段，主要包括数 据清洗、数据增强、困难样本挖掘等⽅法。有害数据过滤是数据精炼的关键环 节，通过识别并剔除对模型训练产⽣负⾯影响的数据，可以有效提升模型的收敛 速度和最终性能。困惑度（ Perplexity ）是衡量模型对数据拟合程度的重要指标， ⾼困惑度的数据通常表⽰模型难以理解或存在标注错误，可作为筛选困难样本 的依据。

在漏洞检测领域，数据精炼研究相对较少，现有⼯作主要关注数据增强和样 本平衡，对于如何从低质量数据集中精炼出⾼质量训练数据的研究仍有待深⼊。
