## 1.3.1 设计基于⼤语⾔模型的漏洞检测⽅法

针对传统⼩模型对复杂漏洞语义建模能⼒不⾜的问题，采⽤⼤语⾔模型 CodeQwen2.5-7B 作为基座模型，设计了⼀套完整的漏洞检测⽅案。核⼼思路 在于，充分利⽤静态分析⼯具在代码切⽚与上下⽂限定⽅⾯的精确性，通过过程 间切⽚技术构建能够覆盖完整缺陷传播路径的代码上下⽂，使模型输⼊尽可能 涵盖与缺陷分析相关的全部语义信息；同时，设计结构化的输出格式，要求模型 明确给出从缺陷触发点（ Source ）到缺陷影响点（ Sink ）的完整数据流路径，⽽ ⾮仅输出⼆元判定结果。这种设计既使模型能够在完整的缺陷上下⽂中进⾏推 理，提升了检测的准确性和可解释性，⼜使输出结果能够直接被开发者理解和 ⽤于漏洞修复，降低了⼈⼯验证成本。

（ 1 ） 模型选择与优化： 综合考虑模型性能与硬件资源限制， 选择 CodeQwen2.57B-chat 作为基座模型。采⽤ QLoRA （ Quantized Low-Rank Adaptation ）微调技术， 通过量化和秩分解⼤幅降低显存占⽤，在单卡 H800 上⽀持 8192 的最⼤上下⽂

长度。

- （ 2 ）轻量级切⽚⽅法：设计了两级切⽚策略--基于调⽤图的粗粒度切⽚和 基于程序依赖图（ PDG ）的细粒度切⽚。调⽤图切⽚通过⼴度优先搜索确定与 Source 语句相关的函数集合， PDG 切⽚进⼀步过滤⽆关代码，仅保留存在数据 依赖和控制依赖的语句。两种切⽚⽅法可结合使⽤，在计算开销和切⽚质量之 间取得平衡。通过静态分析⼯具的精确切⽚，模型只需关注与漏洞相关的代码 ⽚段，⼤幅减少了 Token 消耗和推理时间。
- （ 3 ）任务形式设计：将传统漏洞检测任务重新形式化为 ' 给定 Source ，判断 是否存在可达 Sink' 的数据流判断任务。消融实验表明，不同的任务形式变体 （是否要求输出路径）对检测性能影响较⼩（ F1 分数在 0.934-0.948 之间） 。性能 提升的核⼼在于通过过程间切⽚将能够覆盖完整缺陷上下⽂的代码段作为输⼊， ⽽⾮任务形式的具体设计。但路径信息对于⽤户使⽤模型给出的结果具有重要 价值--它可以帮助开发者快速定位漏洞传播路径，理解漏洞成因，从⽽更⾼ 效地进⾏修复。
- （ 4 ）多级评估体系：提出三级评估指标，⼀级评估检测模型是否正确预测缺 陷存在及 Source 位置，⼆级评估检查预测的 Sink 语句是否与 Source 存在依赖关 系，三级评估验证从 Source 到 Sink 的依赖传递顺序是否合理。该评估体系超越
- 了简单的⼆元判断，全⾯检验模型对漏洞路径的理解能⼒。

## 1.3.2 提出基于核⼼集的增量学习⽅法

针对模型演进过程中的灾难性遗忘问题，提出了⼀种基于参数变化特征的 增量学习⽅法：

- 微调，计算训练前 后模型参数的变化量作为该数据的特征表⽰。相⽐梯度特征，参数变化特征更
- （ 1 ）参数变化特征提取：对每个训练数据独⽴进⾏ LoRA 能反映模型对数据的整体理解，且计算开销更低。
- （ 2 ）层次聚类核⼼集选择：对参数变化特征进⾏随机投影降维后，采⽤层次 聚类算法将相似数据归为⼀类。通过从每个类中随机采样⼀个数据，构建代表 性核⼼集。核⼼集⼤⼩可通过调整聚类数量灵活控制，实现数据多样性的有效 表征。实验表明，仅使⽤ 20% 的核⼼集即可达到与全量数据集相当的性能，训 练时间减少约 45% 。

- （ 3 ）混合相似度算法：综合考虑特征⽅向（余弦距离）和参数数值变化（欧 式距离） ，提出混合相似度度量⽅法。实验表明，该⽅法在保持模型 AUC 接近全 数据集训练结果的同时， Precision 和 Recall 指标显著优于单⼀距离度量⽅法。

## 1.3.3 设计基于数据精炼的质量提升⽅法

针对低质量数据集影响模型性能的问题，提出了⼀种基于模型⾏为分析的

数据精炼⽅法：

- （ 1 ）有害数据识别：利⽤模型在验证集上的错误预测结果构建有害数据集，
- 同时计算模型推理时的平均困惑度，将⾼困惑度数据纳⼊筛选范围。
- （ 2 ）聚类分布过滤：计算有害数据在训练集聚类结果中的分布，过滤掉与有 害数据同属⼀个类别的训练数据，有效剔除潜在的低质量样本。
- （ 3 ）精炼数据集构建：将过滤后的训练数据与⾼困惑度数据重新组合，形成 精炼数据集。该⽅法不仅适⽤于全量数据集，也可与核⼼集⽅法结合，在增量学 习场景下实现数据质量的持续提升。

## 传统漏洞检测⽅法

传统漏洞检测⽅法主要包括静态分析、动态分析和⼈⼯代码审查三类。

静态分析（ Static Analysis ）通过预定义规则对源代码或⼆进制代码进⾏扫 描，识别潜在的安全问题。代表性⼯具包括 Cppcheck [1] 、 Clang Static Analyzer [2] 和 Infer [3] 。这些⼯具采⽤规则匹配、数据流分析等技术，能够在不执⾏程序的情 况下快速检测漏洞。静态分析的优点是分析速度快、覆盖范围⼴，但存在误报率 和漏报率较⾼的问题，且规则更新滞后于新漏洞类型的出现。

## 2.2.2

## 基于深度学习的漏洞检测

基于深度学习的漏洞检测⽅法通过训练⾃动学习代码中的漏洞模式，⽆需 ⼈⼯设计复杂的检测规则，具有更强的适应性和泛化能⼒。

VulDeePecker [4] 是最早将深度学习应⽤于漏洞检测的代表性⼯作之⼀。该 ⽅法将代码表⽰为数据依赖图（ Data Dependency Graph ） ，利⽤双向 LSTM ⽹络 学习代码特征，能够检测缓冲区溢出和缓冲区读取漏洞。 Choi 等⼈ [6] 提出使⽤ Memory Network 从原始代码中端到端地预测缓冲区溢出，⽆需⼿⼯设计特征。

Devign [7] 从四个⼤型 C 语⾔开源项⽬（ Linux Kernel 、 QEMU 、 Wireshark 、 FFmpeg ）中收集并⼈⼯标注了函数级漏洞数据，提出了基于门控图神经⽹络 （ GGNN ）的漏洞检测⽅法，在漏洞检测任务上取得了当时的最优性能。 Fan 等⼈ 构建了 Big-Vul 数据集 [14] ，从开源 GitHub 项⽬中收集了 3754 个 C/C++ 代码漏 洞，涵盖 91 种不同的漏洞类型。

然⽽，现有数据集的质量问题逐渐引起研究关注。 Jain 等⼈ [13] 对 C/C++ 漏 洞检测数据集进⾏了系统性评估，发现现有数据集普遍存在标注错误、漏洞类 型单⼀、正负样本不平衡、上下⽂信息缺失等问题。这些问题直接影响了模型的 训练效果和泛化能⼒。

Ding 等⼈ [15] 的研究进⼀步揭⽰，现有漏洞检测基准测试严重⾼估了代码语 ⾔模型的性能。他们提出的 PrimeVul 数据集采⽤了严格的数据去重和时间顺序 划分策略，缓解了数据泄露问题。评估结果表明，在 BigVul 上表现优异的模型 在 PrimeVul 上性能急剧下降，说明数据质量问题对模型评估的影响深远。

Risse 等⼈ [16] 指出，当前机器学习漏洞检测研究的问题定义存在缺陷，函数 级⼆分类任务缺乏必要的上下⽂信息，模型可能通过虚假相关性获得⾼分⽽⾮ 真正检测漏洞。这⼀发现对漏洞检测任务的评估⽅法提出了重要挑战。

Li 等⼈ [17] 系统研究了 LLM 在漏洞检测任务上的后训练管道，发现基于拒 绝采样的监督微调（ SFT ）显著优于基于理性化的监督，且强化学习（ RL ）⽅法 在偏好优化后能够进⼀步提升性能。 Anthropic 发布的 Claude Code Security [18] 通 过扫描代码库检测安全漏洞并提供针对性修复建议，采⽤多阶段验证流程减少 误报。

## 2.3 ⼤语⾔模型基础

## 2.3.1 Transformer 架构与代码预训练

Transformer 是 Vaswani 等⼈于 2017 年提出的⼀种基于⾃注意⼒机制（ SelfAttention ）的神经⽹络架构 [19] 。 Transformer 摒弃了传统的循环神经⽹络（ RNN ） 和卷积神经⽹络（ CNN ）结构，完全基于注意⼒机制实现序列建模，具有并⾏化 程度⾼、长距离依赖建模能⼒强等优点。

代码预训练与⽂本预训练有所不同，需要考虑代码的特殊性质：代码具有严 格的语法规则；代码不仅有⽂本语义，还有执⾏语义，包括数据流、控制流等； 代码中的变量定义和使⽤可能相隔很远，需要捕捉长距离依赖；实际项⽬通常 包含多种编程语⾔，需要处理跨语⾔的交互。

StarCoder2 [8] 在 619 种编程语⾔的代码数据上进⾏预训练，显著提升了代码 理解和⽣成能⼒。该模型使⽤ 4TB 的代码数据进⾏训练，在多种代码基准测试 上取得了优异成绩。

然⽽， Zhang 等⼈ [20] 的研究表明， LLM 在代码⽣成任务上存在 ' 熟悉度幻 觉 ' （ Specialist in Familiarity ）问题，即模型在当前数据集上的表现可能受到训练 数据泄露的影响。他们提出了基于代码混淆的基准测试 OBFusEvAL ，通过多层 次的混淆策略评估 LLM 在未见代码上的真实能⼒。研究结果表明，经过混淆后， LLM 的测试通过率平均下降达 62.5% ，说明 LLM 在不熟悉代码任务上性能显著 下降，泛化能⼒有限，需要持续演进以适应新的代码模式。

## 2.3.2 ⼤语⾔模型的微调

预训练的⼤语⾔模型虽然学习到了丰富的知识，但要应⽤于特定任务，通常 需要进⾏微调（ Fine-tuning ） 。微调是指在特定任务的标注数据上进⼀步训练模 型，使其适应⽬标任务。

全量微调（ Full Fine-tuning ）是指更新模型的所有参数，通常能够取得最好 的性能，但存在计算开销⼤、存储开销⼤、灾难性遗忘和数据需求⼤等问题。

为了解决全量微调的问题，研究者提出了参数⾼效微调（ Parameter-Efficient Fine-tuning, PEFT ） ⽅法。 PEFT ⽅法的核⼼思想是冻结预训练模型的⼤部分参数， 仅微调少量参数或引⼊少量可学习参数。 Adapter [21] ⽅法在 Transformer 层之间 插⼊⼩型神经⽹络模块，仅训练 Adapter 参数⽽冻结主⼲⽹络。 Prefix Tuning [22] ⽅法在输⼊序列前添加可学习的连续前缀向量，引导模型⽣成特定任务的输出。

LoRA （ Low-Rank Adaptation ） [23] ⽅法通过低秩分解近似参数更新，将参数 更新表⽰为两个低秩矩阵的乘积。对于 GPT-3 ， LoRA 可以将 trainable 参数减少 10000 倍，计算硬件需求减少 3 倍，同时保持与全量微调相当或更好的模型质量。

QLoRA （ Quantized LoRA ） [24] 是 Dettmers 等⼈于 2023 年提出的⾼效微调⽅ 法，结合了量化技术和 LoRA 微调。 QLoRA 的核⼼技术包括： （ 1 ） 4 ⽐特量化： 将预训练模型权重量化为 4 ⽐特，⼤幅降低显存占⽤。 QLoRA 提出了⼀种新的 4 ⽐特数据类型 NF4 （ NormalFloat 4 ） ， 专门针对正态分布的权重进⾏了优化。 （ 2 ） 双重量化：为了进⼀步减少显存占⽤， QLoRA 对量化常数也进⾏了量化，使⽤ 8 ⽐特量化来表⽰ 32 ⽐特的量化常数。 （ 3 ）分页优化器： QLoRA 使⽤分页优化 器（ Paged Optimizer ）来管理显存，当显存不⾜时将优化器状态暂时换出到 CPU 内存，需要时再换回 GPU 。 QLoRA 能够在单张 48GB GPU 上微调 65B 参数模 型，同时保持完整的 16 ⽐特微调任务性能。

## 2.4 增量学习与灾难性遗忘

## 2.4.1 灾难性遗忘问题

灾难性遗忘（ Catastrophic Forgetting ）是神经⽹络在持续学习过程中⾯临的 普遍问题，最早由 McCloskey 和 Cohen 于 1989 年发现。 Kirkpatrick 等⼈ [25] 将这 ⼀问题形式化为克服神经⽹络中的灾难性遗忘，并提出了 EWC （ Elastic Weight Consolidation ）⽅法。当神经⽹络学习新任务或新数据时，参数更新会覆盖之前 学习到的知识，导致模型在旧任务上的性能显著下降。

Toneva 等⼈ [9] 通过实证研究发现，深度神经⽹络在学习新数据时会遗忘之 前学习过的样本。他们提出了 ' 遗忘事件 ' （ Forgetting Event ）的概念，即模型对 某个样本从正确预测变为错误预测的时刻。研究发现，遗忘事件在训练过程中 频繁发⽣，且与样本的难度和代表性有关。基于遗忘动态，可以从训练数据中省 略相当⼀部分样本，同时保持最先进的泛化性能。

在⼤语⾔模型场景下，灾难性遗忘问题更加突出。 Chen 等⼈ [26] 系统⽐较了 监督微调（ SFT ）和强化学习（ RL ）两种后训练⽅法的遗忘模式。实验结果表明， RL ⽐ SFT 导致的遗忘更少，同时能够达到相当或更⾼的⽬标任务性能。这归因 于 RL 使⽤ on-policy 数据的 mode-seeking 特性，能够在学习⽬标任务时保持先 验知识完整。

## 2.4.2 增量学习⽅法分类

Wang 等⼈ [10] 对持续学习进⾏了全⾯综述，将现有⽅法分为三⼤类：基于 回放、基于正则化和基于参数隔离。表 2-2 对⽐了各类增量学习⽅法的特点。

## 基于回放的⽅法

基于回放（ Replay-based ）的⽅法通过保留⼀部分旧数据或使⽤⽣成模型合 成旧数据的代表样本，在训练新任务时同时训练旧数据，从⽽缓解遗忘问题。

经验回放（ Experience Replay ）是最简单的回放⽅法，维护⼀个固定⼤⼩的 回放缓冲区，随机存储旧任务的部分样本。训练新任务时，从缓冲区采样旧样本 混合训练。⽣成回放（ Generative Replay ）使⽤⽣成模型（如 GAN 、 VAE ）学习 旧任务的分布，⽣成合成样本⽤于回放，不需要存储真实样本，但⽣成质量影响 回放效果。

核⼼集选择（ Coreset Selection ）⽅法旨在从旧数据中选择少量代表性样本， 构建核⼼集⽤于回放。 Aljundi 等⼈ [11] 提出了基于梯度的样本选择⽅法（ GSS ） ， 通过计算样本梯度之间的余弦相似度来选择代表性样本。 Yoon 等⼈ [27] 提出了在 线核⼼集选择（ OCS ）⽅法，在每次迭代中选择最具代表性和信息性的核⼼集， 以在线⽅式训练。 Tiwari 等⼈ [12] 提出了梯度核⼼集回放（ GCR ）⽅法，将核⼼ 集选择问题转化为优化问题，选择 closely approximates 当前所有数据梯度的核⼼ 集。

## 基于正则化的⽅法

基于正则化（ Regularization-based ）的⽅法通过在损失函数中添加正则化项， 约束参数更新不偏离旧任务的最优解太远。

EWC （ Elastic Weight Consolidation ） [25] 计算每个参数对旧任务的重要性，对 重要参数的更新施加更⼤的惩罚。 EWC 使⽤ Fisher 信息矩阵近似参数重要性， 能够有效保护旧任务的关键参数。 GEM （ Gradient Episodic Memory ） [28] 利⽤梯度 ⽅向约束新任务的学习不⼲扰旧任务，通过存储旧任务的梯度信息来指导新任 务的学习。

## 基于参数隔离的⽅法

基于参数隔离（ Parameter Isolation-based 数⼦集，避免任务之间的⼲扰。

## 2.4.3 ⼤语⾔模型的增量学习

⼤语⾔模型的增量学习⾯临新的挑战：参数量巨⼤，存储每个样本的梯度 变化计算开销和存储开销都⾮常⾼；任务复杂性，⼤语⾔模型通常处理多任务， 任务边界不清晰；计算资源限制，全量微调⼤语⾔模型需要⼤量计算资源。

Wu 等⼈ [29] 对⼤语⾔模型的持续学习进⾏了系统调研，将持续学习技术分 为持续预训练、指令微调和 alignment 三个阶段进⾏ categorization 。 Wang 等⼈ [30] 提出了 TRACE 基准，⽤于评估⼤语⾔模型的持续学习能⼒。实验结果表明，经 过 TRACE 训练后，对齐的⼤语⾔模型在通⽤能⼒和指令跟随能⼒上均出现显著 下降。

Song 等⼈ [31] 提出了持续参数⾼效微调（ ConPET ）⽅法，将参数⾼效微调 应⽤于持续学习场景。 ConPET 包括静态和动态两个版本，静态版本通过 PET 和 动态回放策略将可训练参数规模减少 3000 多倍，动态版本采⽤独⽴的 PET 模块 和选择器实现可扩展的持续学习。 Cheng 等⼈ [32] 探索了领域持续预训练对⼤语 ⾔模型的影响，发现基于阅读理解的训练⽅法能够显著提升领域性能，同时保 持通⽤能⼒。

在漏洞检测领域， Xue 等⼈ [33] 提出了 VulTypeIL ⽅法，采⽤混合回放策略 和 EWC 正则化缓解灾难性遗忘，结合 focal loss 和 label smooth 处理长尾分布问 题，在软件漏洞类型识别任务上取得了优于现有⽅法的效果。

## 2.5 数据质量与数据精炼

## 2.5.1 数据质量对模型性能的影响

数据质量对深度学习模型的性能有着决定性影响。 Jain 等⼈ [13] 对 C/C++ 漏 洞检测数据集进⾏了系统性评估，发现现有数据集普遍存在标注错误、漏洞类 型单⼀、正负样本不平衡、上下⽂信息缺失和数据泄露等问题。这些问题直接影 响了模型的训练效果和泛化能⼒。

Ding 等⼈ [15] 的研究进⼀步揭⽰，现有漏洞检测基准测试严重⾼估了代码语 ⾔模型的性能。他们提出的 PrimeVul 数据集采⽤了严格的数据去重和时间顺序 划分策略，缓解了数据泄露问题。评估结果表明，在 BigVul 上表现优异的模型 在 PrimeVul 上性能急剧下降，说明数据质量问题对模型评估的影响深远。

## 2.5.2

## 数据精炼技术

数据精炼（ Data Refinement ）是提升数据质量的重要技术⼿段，主要包括数 据清洗、数据增强、困难样本挖掘等⽅法。

数据清洗是指识别并纠正或删除数据中的错误、噪声和不⼀致。规则过滤基 于预定义规则过滤明显错误的数据，如代码⽆法编译、长度异常等。模型辅助清 洗利⽤预训练模型检测异常样本，如使⽤困惑度识别标注错误。⼈⼯审核对可

疑样本进⾏⼈⼯检查和修正，确保数据质量。

困难样本挖掘（ Hard Example Mining ）是指识别模型难以正确预测的样本， 重点训练这些样本以提升模型性能。困惑度筛选计算模型对样本的困惑度，⾼困 惑度样本通常是困难样本。损失筛选选择训练损失⾼的样本进⾏重点训练。错 误样本分析模型在验证集上的错误预测，构建困难样本集。

Xia 等⼈ [34] 提出了 LESS ⽅法，⽤于指令调优中的影响数据选择。 LESS 通 过低阶梯度相似性搜索（ Low-rank gradiEnt Similarity Search ）估计数据影响度， 实验表明在 5% 的数据上训练往往能够优于在全量数据上训练的效果。

Wang 等⼈ [35] 提出了 In-Run Data Shapley ⽅法，在单次训练过程中计算数 据贡献度，实现可扩展的数据归因。该⽅法通过梯度信息⾼效地评估每个训练 样本对最终模型性能的贡献，为数据精炼提供了理论基础。

## 2.6 程序切⽚技术

## 2.6.1 程序切⽚的基本概念

程序切⽚（ Program Slicing ）是由 Weiser 于 1981 年提出的⼀种程序分析技 术，旨在从程序中提取与特定变量或操作相关的代码⽚段。程序切⽚通过分析 程序的控制流和数据流，确定对⽬标变量有影响的语句集合。

形式化地，给定程序 𝑃 、切⽚标准 𝐶 = (𝑞, 𝑉 ) （其中 𝑞 是程序中的某个点， 𝑉 是变量集合） ，程序切⽚是 𝑃 的⼀个⼦集 𝑃 ′ ，满⾜ 𝑃 ′ 在 𝐶 上的⾏为与 𝑃 相同。

前向切⽚（ Forward Slicing ）从切⽚标准出发，找出所有受其影响的语句，⽤ 于分析变量的影响范围。后向切⽚（ Backward Slicing ）从切⽚标准出发，找出所 有影响它的语句，⽤于分析变量的依赖来源。静态切⽚（ Static Slicing ）不考虑 具体输⼊，分析所有可能执⾏路径上的依赖关系，保守但可能包含冗余。动态切 ⽚（ Dynamic Slicing ）基于具体输⼊和执⾏轨迹，分析实际执⾏路径上的依赖关 系，精确但依赖于具体输⼊。

程序切⽚在漏洞检测中具有重要应⽤价值。 Lu 等⼈ [37] 在⼯业级 C++ 库上提出了代码切⽚算法⽤于上下⽂提取，结合多⾓⾊ LLM 的⾃动化代码审查，在关键 bug 包含率（ KBI ）上取得了 2 倍于标准 LLM 升。

Bingham 等⼈ [41] 提出了随机投影⽅法⽤于降维，该技术在处理⾼维代码特 征时可以显著降低计算开销，同时保持数据向量之间的相似性。

两级切⽚⽅法结合了基于调⽤图的粗粒度切⽚和基于 PDG 的细粒度切⽚， 在计算开销和切⽚质量之间取得平衡，为漏洞检测提供⾼质量的输⼊。

## 2.7 本章⼩结

系统回顾了与基于⼤语⾔模型的软件漏洞检测相关的技术与研究⼯作。在 传统漏洞检测⽅法⽅⾯，静态分析、动态分析和⼈⼯审查各有优劣，但均⾯临扩 展性和效率问题。基于深度学习的⽅法通过⾃动学习代码特征，在漏洞检测任 务上展现出巨⼤潜⼒，但现有数据集质量问题和评估⽅法缺陷仍是主要挑战。

⼤语⾔模型为漏洞检测提供了新的技术路径，但其参数量巨⼤导致全量微 调成本⾼昂，参数⾼效微调技术如 LoRA 和 QLoRA 显著降低了微调门槛。增量 学习中的灾难性遗忘问题在⼤语⾔模型场景下更加突出，基于回放、正则化和 参数隔离的⽅法各有特点，但如何在⼤模型场景下⾼效应⽤仍是开放问题。

数据质量对模型性能具有决定性影响，现有漏洞检测数据集普遍存在标注 错误、数据泄露等问题。数据精炼技术通过清洗、增强和困难样本挖掘提升数 据质量，有害数据过滤能够有效剔除对模型训练产⽣负⾯影响的数据。程序切 ⽚技术通过提取与漏洞相关的代码⽚段，为漏洞检测提供⾼质量的上下⽂输⼊， 在⼯业级代码审计中展现出良好应⽤前景。

现有研究为基于⼤语⾔模型的软件漏洞检测提供了坚实的理论基础和技术 ⽀撑，但在⼤语⾔模型漏洞检测的持续演进、数据质量提升和⾼效上下⽂构建 等⽅⾯仍存在研究空间，这也是本研究的出发点。

## 3.1 引⾔

软件漏洞检测是软件安全领域的重要研究课题。传统的漏洞检测⽅法如静 态分析⼯具、动态分析⼯具和⼈⼯代码审查等，虽然在⼀定程度上能够发现软 件中的安全问题，但随着软件复杂性的增加和攻击技术的不断演进，这些⽅法 逐渐显现出局限性。基于规则的⽅法需要专家⼿动编写和维护检测规则，难以 应对新出现的漏洞类型；动态分析⽅法计算开销⼤，难以处理⼤规模程序；⼈⼯

代码审查效率低，⽆法满⾜现代软件开发快速迭代的需求。

针对上述挑战，提出了⼀种基于⼤语⾔模型的漏洞检测⽅法。核⼼思路在 于：充分利⽤静态分析⼯具在上下⽂构建与上下⽂限定⽅⾯的精确性，通过过程 间切⽚技术构建能够覆盖完整缺陷传播路径的代码上下⽂，使模型输⼊尽可能 涵盖与缺陷分析相关的全部语义信息；同时，设计结构化的输出格式，要求模型 明确给出从缺陷触发点（ Source ）到缺陷影响点（ Sink ）的完整数据流路径，⽽ ⾮仅输出⼆元判定结果。这种设计既使模型能够在完整的缺陷上下⽂中进⾏推 理，提升了检测的准确性和可解释性，⼜使输出结果能够直接被开发者理解和

⽤于漏洞修复，降低了⼈⼯验证成本。

## 3.4 上下⽂构建⽅法

在⼤语⾔模型应⽤于代码缺陷检测任务时，输⼊上下⽂的质量直接影响模 型的推理效果。由于软件项⽬通常包含⼤规模代码库，⽽⼤语⾔模型的上下⽂ 窗⼝存在物理限制，如何构建既完整⼜精简的输⼊上下⽂是⾯临的关键挑战。

从上下⽂⼯程（ Context Engineering ）的视⾓出发，设计了基于静态分析的 上下⽂构建⽅法。该⽅法的核⼼⽬标是：在有限的上下⽂窗⼝内，最⼤化保留与 缺陷分析相关的语义信息，同时剔除⽆关代码的⼲扰。上下⽂构建过程遵循可

靠性（ Soundness ）原则，确保不遗漏与缺陷传播路径相关的任何关键代码。

## 3.4.1 Source 锚点识别

上下⽂构建的起点是识别缺陷分析的锚点，即 Source 语句。 Source 语句是 指触发⼀个缺陷所需执⾏的代码⽚段的起始位置，通常是变量定义、函数调⽤、 内存分配等操作。 Source 语句由静态分析⼯具⾃动识别，作为后续上下⽂提取 的参考点。

例如，在空指针解引⽤缺陷中，可能导致空指针的变量赋值语句即为 Source 语句；在缓冲区溢出缺陷中，未进⾏边界检查的数组访问语句即为 Source 语句。

## 3.4.2 函数级上下⽂提取

在识别 Source 语句后，需要确定与之相关的函数集合。软件缺陷往往不是 局限于单个函数内部，⽽是沿着函数调⽤链传播。因此，上下⽂构建需要跨越函 数边界，捕捉完整的缺陷传播路径。

基于调⽤图（ Call Graph ）的函数级上下⽂提取⽅法如下：从包含 Source 语 句的函数出发，沿调⽤边向上追溯调⽤该函数的函数集合（调⽤者） ，沿被调⽤ 边向下追踪被该函数调⽤的函数集合（被调⽤者） 。追溯深度根据缺陷类型和代 码复杂度动态调整，通常设置为 3-5 层即可覆盖绝⼤多数缺陷传播路径。

函数级上下⽂提取在计算开销和覆盖范围之间取得平衡，能够快速确定与 缺陷分析相关的函数范围，为后续的语句级筛选奠定基础。

## 3.4.3 语句级上下⽂筛选

函数级上下⽂提取可能包含⼤量与缺陷分析⽆关的代码。为进⼀步提升上 下⽂的信噪⽐，需要在每个函数内部进⾏语句级筛选，仅保留与 Source 变量存 在依赖关系的语句。

基于程序依赖图（ Program Dependence Graph, PDG ）的语句级上下⽂筛选⽅ 法如下：⾸先构建函数内部的程序依赖图，识别数据依赖和控制依赖关系；然 后从 Source 语句出发，沿依赖边进⾏双向遍历--后向遍历收集所有可能影响 Source 语句执⾏的语句（依赖来源） ，前向遍历收集所有可能被 Source 语句影响 的语句（影响⽬标） ；最后合并后向和前向遍历的结果，形成语句级上下⽂。

语句级上下⽂筛选能够有效剔除函数内部的⽆关代码，显著减少输⼊ Token 数量，降低模型推理成本，同时保持缺陷传播路径的完整性。

## 3.4.4

## 上下⽂组合策略

函数级上下⽂提取和语句级上下⽂筛选可以灵活组合使⽤，以适应不同的 场景需求：

组合模式 ：先使⽤函数级上下⽂提取确定涉及的函数集合，再使⽤语句级上 下⽂筛选在每个函数内部进⾏精细筛选。这种组合策略在保持上下⽂可靠性的 同时，有效减少了输⼊ Token 数量，是推荐的标准配置。

独⽴模式 ：当计算资源有限或需要快速处理⼤量代码时，可以仅使⽤函数级 上下⽂提取；当需要⾼精度的上下⽂结果或处理复杂缺陷时，可以仅使⽤语句

级上下⽂筛选。

通过上述上下⽂构建⽅法，能够在有限的上下⽂窗⼝内，为模型提供包含完 整缺陷传播路径信息的⾼质量输⼊，为后续的模型推理奠定基础。需要强调的 是，上下⽂构建的核⼼价值在于实现从过程内分析到过程间分析的跃迁。实验 表明，正是这种分析范围的扩展--⽽⾮任务形式的具体设计--是检测性能 提升的根本来源。
