# TeX_Agent 核心系统设计方案：LaTeX 结构理解与智能诊断体系

## 一、 引言与系统概述
在学术科研领域，LaTeX 是高质量论文排版的标准工具，但由于其宏语言的图灵完备性，传统的文本处理手段或单纯依赖大语言模型（LLM）的“生读硬解”极易导致结构迷失、上下文割裂及高昂的 Token 成本。

**TeX_Agent** 旨在构建一个结合“本地轻量级静态解析”与“云端无状态大模型推理”的多智能体写作协作系统。本方案聚焦于系统如何深度理解 LaTeX 复杂结构、高效捕捉语法与编译错误、在自动保存（Auto-Save）环境下优化前端实时交互，以及如何利用工程化手段克服 LLM 无状态限制，实现精准、低延迟、可操作的论文润色与审查。

---

## 二、 LaTeX 结构化理解与局部上下文管理

### 2.1 抽象语法树（AST）本地解析
系统拒绝采用模糊的正则表达式处理源码，而是引入传统的编译解析技术：
* **技术选型**：使用 `Tree-sitter-latex` 或 `TexSoup` 作为核心解析引擎。
* **结构化映射**：将 `.tex` 源码解析为多层级的 AST 树状结构。能够精准识别并分离出文档的前言区（Preamble）、环境区（Environments，如 `\begin{abstract}`、`\begin{figure}`）及章节层级（Sections/Subsections）。

### 2.2 多文件项目“展平”预处理（Flattening）
复杂的 LaTeX 模板通常利用 `\input{}` 或 `\include{}` 引入子文件结构。
* **递归展平**：本地预处理器在加载主文件 `main.tex` 时，会自动递归读取、解析并将其中的子文件节点无损替换到主内存树中，形成完整的项目依赖视图，避免 Agent 产生跨文件信息遗漏。

### 2.3 局部轻量级数据库（隔离全局 RAG）
* **防止知识污染**：系统严格分离外部检索库（如海量 arXiv 文献、Checklist 专家库）与当前正在写作的论文草稿。
* **内存上下文数据库**：将解析出的 AST 节点或分块文本打上元数据标签（例如 `{"chapter": "Method", "section": "3.2 Architecture", "type": "paragraph"}`），存入内存数据库（如内存模式的 SQLite 或 Python Dict 索引树）。
* **性能优势**：单篇论文的数据量在内存中仅数 MB。基于内存索引的存取开销极低（<5ms），远快于每次重新读取磁盘并用正则扫描的速度，能完美支撑多 Agent 节点的高并发异步读取。

## 三、 语法与编译错误多级诊断机制

LaTeX 的排版警告、交叉引用（Cross-references）及 BibTeX 文献依赖往往需要多次编译才能收敛。系统建立了一套“静态+动态+语义反思”的多级审查工具链路。

[代码变更] -> 1. 静态检查 (ChkTeX) -> 2. 自动化试编译 (latexmk) -> 3. 报错切片打包 -> 4. LLM 语义诊断

### 3.1 核心链路设计 

1.  **第一级：静态语法扫描 (Linter)** 

   * **工具**：封装本地 `ChkTeX` 命令。
   * **作用**：在 10-50ms 内瞬间捕捉漏掉的括号、环境不匹配、标点符号误用等低级低延迟语法警告，并精确定位行号。 

2.  **第二级：自动化多轮试编译 (Compiler)** 

   * **工具**：集成 TeX 发行版自带的自动化构建脚本 `latexmk`。    
   * **命令**：`latexmk -pdf -interaction=nonstopmode main.tex`
   * **作用**：`latexmk` 会自动读取 `.log`、`.aux`、`.bbl` 文件，自主判断并执行所需次数的重编译，直至交叉引用和交叉文献彻底收敛。系统无需自行编写繁琐的重编译计数逻辑。

3.  **第三级：LLM 语义反思与修改建议 (Reflection Agent)**    

   * **动作**：若编译失败，系统捕获末轮生成的 `.log` 文件，精确提取出带有 `!` 的 Fatal Error 行号及错误原因。  
   * **切片投喂**：不将全量源码发给 LLM，而是切取报错行及其前后 10 行的源码片段，配合报错日志作为上下文投喂给 Reflection Agent。LLM 此时只需专注于“根据编译器日志解释原因并给出修改后的 LaTeX 代码段”。

## 四、 异步深检查与前端交互优化（对抗自动保存）

若用户在 VS Code 或 Web 编辑器中开启了高频自动保存（如每 500ms 触发一次 `Save`），直接绑定编译和 LLM 调用会导致本地 CPU 卡死、API 账单爆炸以及标注错位。系统引入**“防抖 + 强制取消 + 脏区标记 + 阶梯触发”**的四层防御架构：

### 4.1 四层防御交互架构

| 检查层级 | 触发条件 | 执行动作 | 性能与开销 | 用户感知 |
| :--- | :--- | :--- | :--- | :--- |
| **L0：前端实时** | 键盘任意敲击 | 正则表达式/基础高亮。 | 毫秒级（<10ms），无开销。 | 括号配对、实时高亮。 |
| **L1：本地静态** | 打字停顿 > 0.5s | 触发本地内存或轻量 `ChkTeX` 扫描。 | 极低延迟（<50ms），仅本地 CPU。 | 低级语法红线瞬间显现。 |
| **L2：异步编译** | 用户静默 > 3.0s | 本地后台静默调用 `latexmk -pdf -draftmode` 试编译。 | 延迟 300ms - 1.5s，本地多核并发。 | 后台静默验证，全绿则无感。 |
| **L3：云端深检** | L2 编译失败 或 用户手动发起 | 本地提取脏区代码与报错切片，包装后发起远端 LLM API 请求。 | 延迟 1.5s - 4.0s，消耗 API Token 成本。 | 智能修改建议以“幽灵文本”或悬浮卡片悄然出现。 |

### 4.2 请求强制取消机制（Abort Controller）
* 当用户停顿 3.0s 触发了 L2/L3 深检查，但在大模型或编译器尚未返回结果时，用户又按下了键盘——此时，之前的请求已变为**过期状态（Stale）**。
* 系统必须通过 `AbortController` 或 Python `asyncio.cancel()` **立刻中止**正在排队的编译进程，并**切断**未返回的远端 API 请求，彻底杜绝过期标注错位画线的现象，最大限度节省 Token 和本地算力。

## 五、 无状态 API 的工程化上下文组装（脏区分析法）

大模型 API 本身是**无状态（Stateless）**的，它不记得上一次请求的内容。系统必须在**本地胖客户端维护状态**，并在发送 Prompt 前完成数据的“增量切片”预处理。

### 5.1 本地 AST 脏区标记（Dirty Checking）
* 在内存中始终保留一份“上一次完全编译成功”的 AST 树。
* 当防抖计时器到期准备调用 LLM 时，本地系统将当前最新源码解析为新 AST，两树对比，精准标出哪些节点（如某个 `Paragraph` 或 `Subsection` 节点）被修改，将其打上 **“脏（Dirty）”** 标记。

### 5.2 精准无状态 Prompt 动态组装
系统绝不将整篇 20 页的论文发给大模型，而是利用本地计算出的“脏区节点”，重组出一个极简的“窄上下文” Prompt 发送给云端：

```markdown
【System】
你是一个专业的 LaTeX 语法与内容审查专家。请作为精密的手术刀，仅针对给定的残片进行诊断。

【局部上下文元数据】
当前所属章节：第 3 章 Method -> 3.2 节 System Architecture
论文核心目标：构建多智能体协作系统以提升 LaTeX 写作效率

【待检查的脏区源码（仅限此部分）】
\begin{purple}
In this module, the TeX_Agent uses a tree-sitter parser to extract the AST, 
which allow it to find the missing bracket} quickly.
\end{purple}

【本地 Linter/编译器报错日志】
ChkTeX Warning 15: No match found for '}' at line 42.

【任务指令】
请仅针对上述【待检查的脏区源码】，结合报错日志修正错误，并全中文输出符合学术规范的修改建议。

```

### 5.3 跨章节级联污染与依赖图（Dependency Graph）

如果用户的局部修改涉及全局引用（例如在 Method 章节删除了一个 `\label{fig:arch}`，导致之后 Result 章节的 `\ref{fig:arch}` 产生未定义编译错误）：

1. 本地分析引擎通过**局部依赖图**发现该标签被其他多个章节节点引用。
2. 本地自动将那些受到级联波及的远程引用节点一并激活、标记为“脏区”。
3. 重组 Prompt 时，将“修改源节点”与“受影响的目标节点”打包一同推给无状态的 LLM，从而让大模型在完全不知道前几次交互历史的前提下，依然具备解决跨章节全局引用冲突的能力。
