# 2026-04-28 工作记录

## 今日摘要

今天主要在 **TeX Agent Web UI** 上做了三件事：

1. **Plan 模式不再「跑完才出图」**：后端用 NDJSON 流式响应，规划、构图结束后立刻下发 `plan_graph`，前端马上刷新左侧工作流图，再边跑边等最终回复。
2. **工作流图示支持执行高亮**：利用 LangGraph 的 `stream` + `updates` 批次，把当前步骤涉及的节点通过 `exec_nodes` 推给前端，在预览里用脉冲描边标出；并说明了「长耗时 LLM 调用期间可能暂时没有新事件」这一限制。
3. **Task 模式与 Plan 对齐**：同样支持 `stream: true` 的 NDJSON；首包发 `workflow_graph`（注册表或 `__web__` 草稿），再发多段 `exec_nodes`，最后 `result`；顺带抽取了 `_registry_workflow_draft_sync`，与 `GET /api/workflow/graph` 共用加载逻辑。

涉及代码主要在 `core/agent_cli.py`、`ui/web/server.py` 以及静态资源 `app.js`、`workflow_builder.js`、`styles.css`。

---

## 1. Plan 模式：规划完成后立即展示工作流图（流式 NDJSON）

**问题**：原先 Plan 整条链路跑完后，`/api/chat` 才一次性返回 JSON，前端只能在请求结束时调用 `applyTexAgentPlanGraph`，左侧图示出现太晚。

**方案**：

- **`core/agent_cli.py`**
  - 抽出 **`build_plan_graph_and_app(user_input, branch=None)`**：完成规划、`from_task_plan`、`build_graph`，返回 `(nodes, edges, app)`，不执行 `invoke`。
  - **`run_plan_task`** 改为先调用它，再 **`_execute_with_app`**，避免重复逻辑；结束后照旧写入 `metadata["__plan_graph__"]`。
- **`ui/web/server.py`**
  - **`ChatRequest.stream_plan`**（后与 **`stream`** 统一，见下文）：Plan 为 true 时返回 **`StreamingResponse`**，`Content-Type: application/x-ndjson`。
  - 首行：`{"type":"plan_graph","plan_graph":{...}}`（规划与构图完成后立刻下发）。
  - 随后：执行过程中的 **`exec_nodes`**（见第 2 节）、最后 **`{"type":"result","reply":...,"error":...}`**。
  - 规划阶段失败：`{"type":"error","detail":"..."}`。
  - 非流式（不传流式标志）仍为原 **`ChatResponse` JSON**，兼容旧客户端。
- **`ui/web/static/app.js`**
  - Plan 下 **`fetch` + `ReadableStream`** 按行解析 NDJSON；收到 **`plan_graph`** 即 **`applyTexAgentPlanGraph`**，助手气泡改为「规划已完成，正在执行工作流…」；最后按 **`result`** 渲染 Markdown。

## 2. 工作流图示：执行过程中高亮「当前步骤」节点

**说明**：高亮数据来自 LangGraph **`stream_mode` 的 `updates` 批次**（该批次里刚把状态写回图的节点）。节点内长时间 LLM 推理尚未返回时，可能暂时没有新的 `updates`，高亮会停在上一步结束的节点上，这是图引擎事件粒度限制。

**后端**：

- **`core/agent_cli.py` — `_execute_with_app`**
  - 新增可选参数 **`on_graph_progress: Callable[[List[str]], None]`**。
  - 若提供且编译图支持 **`.stream`**，则使用 **`stream_mode=["updates","values"]`** 流式执行；每个 **`updates`** 批次解析出节点 id 列表并回调；拿不到流或失败则回退 **`invoke`**。
  - 传入 **`on_graph_progress` 时不再走终端 `use_loading` 转圈**（与 Web 进度二选一）。
  - 兼容部分版本返回 **tuple `(mode, payload)`** 的流事件格式。
- **`ui/web/server.py`**
  - Plan 流式路径里在后台线程执行 **`_execute_with_app(..., on_graph_progress=...)`**，通过 **`queue.Queue`** 把进度交给异步生成器，NDJSON 中增加 **`{"type":"exec_nodes","node_ids":[...]}`**。

**前端**：

- **`ui/web/static/workflow_builder.js`**
  - 预览里每个节点 `<g>` 增加 **`data-wf-node-id`**。
  - 导出 **`window.setTexAgentWorkflowActiveNodes(nodeIds)`**，给对应节点加/删类名 **`wf-node-exec-active`**。
- **`ui/web/static/app.js`**
  - 解析到 **`exec_nodes`** 时调用 **`setTexAgentWorkflowActiveNodes`**；收到 **`result` / `error`** 或 **`catch`** 时清空高亮。
- **`ui/web/static/styles.css`**
  - **`.wf-node-exec-active .wf-node-rect`**：蓝色描边 + **`wf-node-exec-pulse`** 轻微脉冲动画。

## 3. Task 模式同样支持流式 + 执行高亮

**动机**：Task 与 Plan 一致，希望在对话执行过程中左侧图与 **`exec_nodes`** 同步，而不是等整段跑完。

**后端**：

- **`ChatRequest`**
  - 新增 **`stream`**；与旧字段 **`stream_plan`** 合并判断：**`use_stream = body.stream or body.stream_plan`**，任一 true 即 NDJSON。
- **`ui/web/server.py`**
  - **`_registry_workflow_draft_sync(name)`**：从注册表加载与 **`GET /api/workflow/graph`** 一致的 **`WorkflowDraftIn`**，避免重复代码。
  - **`_workflow_stream_graph_payload(cli, workflow_name)`**：生成 Task 流式首包图示（**`__web__`** 用内存稿；否则用注册表）。
  - **`body.mode == "task" and use_stream`** 时：**`workflow_graph`** → **`exec_nodes`** → **`result`**；构图失败或执行错误按行返回错误/result。
  - **`GET /api/workflow/graph`** 改为内部调用 **`_registry_workflow_draft_sync`**。

**前端**：

- **`app.js`**：Task 与 Plan 均发 **`payload.stream = true`**；NDJSON 在两种模式下启用；处理 **`workflow_graph`**（与 **`plan_graph`** 同样走 **`applyTexAgentPlanGraph`**），助手气泡为「正在执行任务…」。

## API 行为小结（自测时可对照）

- **流式**：`POST /api/chat`，`stream: true`（Plan 仍可用旧字段 **`stream_plan: true`**）。
- **Plan NDJSON 行类型**：`plan_graph` → `exec_nodes`（多次）→ `result`；规划失败可为 `error`。
- **Task NDJSON 行类型**：`workflow_graph` → `exec_nodes`（多次）→ `result`。
- **非流式**：不传 `stream`/`stream_plan`，响应仍为 JSON **`ChatResponse`**，行为与改造前一致。
