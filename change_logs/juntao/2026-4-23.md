## 四、`runtime_memory` 接线与会话化（演进过程 + 最终形态）

### 4.1 中间形态（对话前半：RAG 式共享槽）

- **`workflow/nodes.py`**：**`make_agent_node`** 将 **`runtime_memory`** 传入 **`ctx.build(..., memory=runtime_memory)`**。  
- **`workflow/graph_builder.py`**、**`workflow/workflow_parser.py`**、**`core/agent_cli.py`**：构图时从 CLI 注入 **`memory_system["shared"]`**（**`BranchMemory`**，默认 **`memory_store/shared.jsonl`**）。

### 4.2 最终形态（对话结论：memory 与 messages 同生命周期）

- **问题**：不希望「memory」承载图内结构化状态，而应与**每次会话 / 分支对话**一致。  
- **`context/context_manager.py`**  
  - 新增 **`ContextManager.search(query, limit, state=None)`**：在 **`state["messages"]`**（优先）或 **`self._messages`** 上构造临时 **`SimpleMemory`** 做检索，**不写 `metadata`、不写 jsonl**。  
  - **`build(...)`**：调用 **`memory.search(..., state=state)`**；对仅支持 **`query, limit`** 的旧实现 **`TypeError` 回退**。

- **`core/agent_cli.py`**  
  - **`_build_app_for_workflow`**、**`run_plan_task` → `build_graph`**： **`runtime_memory=self.context`**（与 **`context_manager`** 同源），**不再**在推理路径上使用 **`memory_system["shared"]`** 作为 **`ctx.build`** 的检索源。

### 4.3 历史加载与消息规范化（对话中已强调）

- **`core/agent_cli.py`** 中从 Context 注入 **`initial_state["messages"]`** 时，对历史项使用 **`ensure_message`** / **`normalize_messages_for_state`**，避免裸 dict/str 导致下游不一致。

## 五、`memory_store` 不落盘：原因与修复

### 5.1 原因

- **`runtime_memory`** 改为 **`self.context`** 后，主路径**不再**对 **`BranchMemory.save()`** 产生调用，**`memory_store/shared.jsonl`** 可能长期为空。  
- **`design` / `think` / `execute`** 槽位若未被显式工具或代码 **`save`**，对应 **`private_*.jsonl`** 亦可为空（属预期，除非另有写入方）。  
- **`use_branch=False`** 时，原 **`shared`** 为 **`SimpleMemory`**，**无 `persist_path`**，即使用代码 `save` 也**无法**写入 **`memory_store`**。

### 5.2 修复（`core/agent_cli.py`）

- **`_persist_new_messages_to_shared_memory_store`**：在 **`_execute_with_app`** 中，与 **`context.save`** 同一批「本轮新增消息」，逐条 **`memory_system["shared"].save(...)`**，追加到 **`memory_store/shared.jsonl`**（metadata 含 **`branch`、`workflow`、`role`、`source_*`** 等）。  
- **`switch_branch`**：对 **`branch_enabled`** 的记忆实例调用 **`memory.switch_branch(branch_name)`**，与 CLI 分支对齐。  
- **`_init_memory_system`**：当 **`use_branch=False`** 时，**`shared`** 改为 **`MemoryFactory.create_shared_memory(branch_enabled=False)`**，保证 **`shared.jsonl` 可持久化**。

### 5.3 分工小结

| 机制 | 作用 |
|------|------|
| **`ctx.build` + `runtime_memory=self.context`** | 推理时 **`<context type='memory'>`** 来自**当前会话消息**检索。 |
| **`_persist_new_messages_to_shared_memory_store`** | 任务结束后把**新增对话**写入 **`shared.jsonl`**，便于跨重启与 **`show_status`** 统计。 |
| **`memory_store/user_persona.json`** | 全局用户画像，与会话记忆分离。 |

## 七、设计共识

### 7.1 `state["metadata"]` vs `state["messages"]`

- **`metadata`**：节点结构化产出、**`__execution_order__`**、**`branch` / `workflow` / `__run_output_dir__`** 等「图执行黑板」。  
- **`messages`**：对话轨迹（含节点拼出的 **`user_msg` 大包** 与 **`assistant`** 回复等）。

### 7.2 内部 Agent 节点的输入 / 输出

- **输入（拼进单条 `prompt`）**：**`[你的具体任务]`**（**`subtask` 或 `state.input`**）→ **`[上游节点输出]`**（**`depends_on` + `metadata`**）→ **`[原始任务背景]`**（**`state.input`**）→ **`[历史上下文]`**（**`ctx.build`**： **`retrieved` / `memory` / `metadata_chain` 或 `history`**）→ **`inline_contracts`**（人格头、单轮契约、终节点说明、输出格式等）。  
- **输出**：**`metadata[node_id]`** 结构化结果；**`messages`** 增量（**`user_msg` + `resp`**）；**仅终节点**写 **`state["output"]`**；**`ctx.save`** 受 **`history_mode`** 与是否终节点约束（与 **`state.messages` 追加** 不是同一回事）。

### 7.3 `ctx` 与「拼接」

- **`ctx`**：**`ContextManager`** 实例。  
- **「拼接」**：主要指 **`ctx.build`** 把 **`retrieved`、`memory` 检索条、`metadata_chain` 或 `history`** 组装成一段 **`[历史上下文]`** 文本，而非简单把全量 message 与全量 memory 各贴一遍。

### 7.4 `minimal` vs `full`（与 4-14 日志一致）

- **`minimal`**：**`ctx.build`** 主历史为 **`metadata_chain`**，仍可带 **`memory` / `retrieved`**；**`full`** 才在 **`ctx.build`** 中带 **`messages` 窗口式 `history`**。  
- 无论哪种模式，**`_finalize_node_state`** 仍可向 **`state.messages`** 追加增量（详见 **`workflow/nodes.py`**）。
