# 2026-04-14 变更摘要（Juntao）

面向论文辅助 Agent 工作流与记忆的改造，便于他人快速了解当日实现范围。

## 1. 工作流消息策略（`workflow/nodes.py`、`workflow/graph_builder.py`、`context/context_manager.py`、`config/planner_config.py`）

- 引入 **`history_mode`**：`full`（与旧行为类似，累积 `state.messages`）与 **`minimal`**（不在 `messages` 里堆中间轮次）。
- **全局默认** `DEFAULT_HISTORY_MODE`（当前为 `minimal`）；构图参数 `default_history_mode` 与节点 `config.history_mode` 可覆盖（节点优先）。
- **上游上下文**：`depends_on` 注入 **完整 `result` + 摘要**，满足强依赖链式任务。
- **`minimal`**：`ctx.build` 在无对话窗口时用 **`metadata` + `__execution_order__`** 合成 `<context type='metadata_chain'>`；仅**汇节点** `ctx.save`；**不再**向旧的图内 `shared_memory` 做节点级 `save`。
- 保留键扩展：`__run_output_dir__` 等不参与 metadata 链展示。

## 2. 节点 I/O 落盘（`workflow/run_dump.py`、`core/agent_cli.py`）

- 每次 CLI 执行任务创建 **`output/YYYYMMDD_HHMMSS/`**，路径写入 `metadata["__run_output_dir__"]`。
- 各节点写 **`{node_id}_input.txt` / `{node_id}_output.txt`**（内容截断），便于核对实现；失败时仍会写 input + error。

## 3. BranchMemory 文件持久化（`memory/branch_memory.py`、`memory/factory.py`）

- 共享/私有记忆默认落盘到 **`memory_store/*.jsonl`**（追加 + 清空/合并/删分支时重写）；与「用户画像」分离，仍为分支实验等场景服务。

## 4. 全局用户画像 User Persona（`memory/persona_memory.py`、`workflow/nodes.py`、`workflow/graph_builder.py`、`core/agent_cli.py`、`workflow/workflow_parser.py`、`config/planner_config.py`）

- **单文件** `memory_store/user_persona.json`，**与分支、节点解耦**，多次启动 `main.py` 共用；CLI 持有 `UserPersonaMemory` 实例并传入动态图。
- 各节点在 **system 段最前**注入 `format_for_prompt()` 的画像 JSON。
- **仅拓扑入口节点**在输出 JSON 中带 **`persona_memory_update`**；说明见 **`PERSONA_ENTRY_NODE_FORMAT_ADDON`**。
- **`action`** 支持：`none`、`merge`（可选 **`remove`** 从列表按精确项删）、**`set`**（**`fields`** 整字段覆盖，字符串可用 `""` 清空）、**`clear`**（**`clear_keys`** 恢复默认空字段）。典型场景：偏好从中文改为英文用 `set` + `fields.writing_preferences`。
- `build_dynamic_graph` / `build_app_from_workflow` 参数由 **`shared_memory` 改为 `persona_memory`**；`run_plan_task` 构图时同样传入 `persona_memory`。
- **`clear_all`** 会重置用户画像；**`status`** 显示画像文件路径。
