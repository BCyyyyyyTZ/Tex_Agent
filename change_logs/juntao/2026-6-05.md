# 2026-06-05 工作记录

## 今日摘要

今天主要在 **Overleaf 编辑器**（`ui/overleaf/`）上修复 PDF 编译与预览链路，并增强 PDF 缩放、选中文本润色两项体验。

涉及文件：`ui/overleaf/server.py`、`ui/overleaf/static/editor.js`、`editor.html`、`editor.css`，新增 `static/vendor/pdf.min.js`、`pdf.worker.min.js`。

---

## 1. PDF 编译：output/ 目录与成功判定

**问题**：
- 编译显示成功，但项目下无 `output/` 目录
- `/api/projects/{id}/pdf` 路由曾被误删，残留代码落在 `if __name__ == "__main__"` 之后，从未注册

**修复**：
- 恢复 PDF 服务路由；编译使用 `-output-directory` 将产物写入 `output/`
- 新增 `_is_valid_pdf()`、`_resolve_compiled_pdf()`：跳过 0 字节占位文件，优先 `output/output.pdf` → `output/{stem}.pdf` → 项目根目录
- 编译成功条件改为 **PDF 实际存在且非空**，不再仅看 `pdflatex` 返回码
- 始终使用 `project.json` 中的 `main_tex`，避免误编译当前打开的子文件

---

## 2. PDF 预览：从无法显示到稳定渲染

**问题（按排查顺序）**：
1. 缺少 PDF 路由 → iframe 404
2. `Content-Disposition: attachment` → 浏览器尝试下载而非内嵌
3. Windows 下 `<embed>` + Blob URL →「无法打开此文件」
4. PDF.js 直接传 `ArrayBuffer` → 误判为空（`.length` 为 `undefined`）
5. 编译后再 fetch PDF → 竞态导致读到 0 字节；空 `output.pdf` 被优先返回

**修复**：
- 引入 **PDF.js**（Canvas 渲染），本地 vendor 资源，不依赖系统 PDF 插件
- 传参改为 `new Uint8Array(data)`
- 编译接口直接返回 **`pdf_base64`**，预览不再依赖第二次 HTTP 请求
- PDF GET 接口改为 `Response` 读字节返回，带 `Content-Length` 与 `Cache-Control: no-store`
- 防重复编译（`compiling` 标志 + Ctrl+Enter 拦截）、渲染 token / AbortController 取消过期任务

---

## 3. PDF 缩放：默认适应高度

**需求**：分辨率可调，默认一页高度刚好填满预览区。

**实现**（PDF 预览栏工具条）：
- `−` / `+`：10% 步进（50%–200%）
- 滑块精细调节
- **「适应高度」**：恢复默认，按预览区高度计算 `scale = viewerHeight / pageHeight`
- 拖动面板分隔条、`ResizeObserver` 监听预览区尺寸变化时自动重绘

## 4. 选中文本润色

**问题**：
- `editor.html` 中存在两个相同 id 的 `polishSelectionBtn`，按钮无效
- 按钮文案乱码，位置固定在右下角
- 后端未使用 `selected_text`，选区润色与全文润色无区别

**修复**：
- 编辑器内保留唯一「润色」浮动按钮，选中文本后出现在选区附近
- 点击后打开润色侧栏并自动请求 AI；后端以选中文本为 `target_text`、全文为上下文
- `selected_text` 存在时可不填 query，默认提示「请润色以下选中文本…」
- 应用润色时优先按 `selectionRange` 精确替换，再 fallback 到字符串匹配
