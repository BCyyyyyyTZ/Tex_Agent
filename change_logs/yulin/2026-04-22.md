## 一、Checklist 注释质量优化

### 1.1 `tools/pdf_comment_tool.py` — 搜索前剔除 Markdown 语法

**问题**：Docling 将 PDF 解析为 Markdown 后，章节标题会携带 `##`、`**`、`` ` `` 等标记。
LLM 从 `export_texts` 中直接复制了含 `##` 的 text_quote（如 `## 范式怎样跑：...`），
但 `pdf_comment_tool` 在 PDF 中搜索原始文本时找不到 `##` 符号，导致定位失败。

**修复**：在 `_batch_annotate()` 方法中，搜索前先用正则剥除 Markdown 标记：

```python
clean_text = re.sub(r'^#{1,6}\s*', '', norm_text)       # 行首 # 标题
clean_text = re.sub(r'\*{1,3}([^*]+)\*{1,3}', r'\1', clean_text)  # **bold**
clean_text = re.sub(r'`[^`]*`', '', clean_text)         # `code`
search_text = clean_text.strip() if clean_text.strip() else norm_text
```

搜索顺序为：`search_text → norm_text → 原始 text → fuzzy(search_text) → fuzzy(norm_text)`。

### 1.2 `config/workflow_checklist_annotate_v3.json` — 全面重写 Checker 提示词

**问题根因分析**（23 条注释中约 9 条为误报）：

| 误报类型 | 典型案例 | 原因 |
|----------|----------|------|
| OCR 噪音被当成作者问题 | `300ms ，随后` 中的空格被标为「排版错误」 | Docling OCR 引入的伪影 |
| 文档类型理解错误 | `linktr.ee/alljoined1` 被标为「数据入口不完整」 | 把读书笔记当成正式论文审查 |
| 注释位置与内容不符 | `[摘要]` 类注释标在正文第5页 | 摘要问题应定位到摘要节本身 |
| 伪问题 | `图呈现 300ms` 被要求「对比实验支撑」 | 实验描述无需对比实验 |

**修复方案**：为每个 checker 的 `system_prompt` 增加：

1. **文档背景声明**：明确该文档是「读书笔记/数据集补充说明」而非正式投稿论文
2. **OCR 白名单**：显式列出不得视为作者问题的 OCR 伪影（Kangxi 部首字符、中文字间空格、标点前空格等）
3. **禁止报告清单**：每个 checker 列出特定的不合理报告场景

`annotation_formatter` 节点增加显式过滤规则（7 条），去除以下类型：
- OCR 引入的间距问题
- 把「缺少对比实验」附到实验描述句上
- 把摘要问题标注到正文位置
- 标注合法 Linktree 链接为不完整

`final_report` 节点增加文档类型上下文，区分「P0 必须修改」与「OCR 解析限制（作者无法修改）」。

**效果**：注释数量从 23 条降至 14 条，误报率从约 40% 降至约 7%，所有有 text_quote 的注释精确命中率 11/11（100%）。

## 二、新增工具（支持完整学位论文审查）

> **背景**：目标 PDF（`201220197-崔晨琦-SMT求解器...54页.pdf`）因 Docling 无法处理 20+ 页文档，
> 需要替代解析方案，以及参考文献、图表引用等专项检查工具。

### 2.1 `tools/pymupdf_parse_tool.py` — `pymupdf_parse`

**功能**：用 PyMuPDF（fitz）直接提取 PDF 文字层，无页数限制，速度极快（54 页 < 0.1s）。

**输出格式与 `docling_parse` 完全兼容**：
- 同样输出 `output_dir / markdown_path / json_path` 元数据
- JSON 格式：`{"texts": [{"text": "...", "label": "section_header"|"text", "prov": [{"page_no": N}]}]}`
- 下游的 `docling_search`、`markdown_section` 可直接复用

**标题识别启发式**（专为中文学位论文调优）：
- 字号 ≥ 正文 1.15x（适配学位论文 14pt/12pt 的标题/正文比）
- 正则匹配中文章节关键词：`第X章`、`参考文献`、`致谢`、`摘要`、`Abstract` 等（长度 ≤ 30 字）
- 过滤目录点线行（含 `....` 的行不识别为标题）
- 章节级→H1，小节编号（`1.2`）→H2，其余→H3

**缓存机制**：输出目录命名为 `{stem}_pymupdf_{timestamp}`，与 docling 缓存共存互不干扰。

---

### 2.2 `tools/chapter_index_tool.py` — `chapter_index`

**功能**：从 Markdown 文件构建全文章节结构树，支持三种输出模式：

| 模式 | 说明 | 典型用途 |
|------|------|----------|
| `tree`（默认）| 带缩进的可视化大纲，标注孤立子节 | LLM 结构检查 |
| `json` | 结构化 JSON 数组（含层级/字符数/子节数） | 工具间传递 |
| `stats` | 统计摘要（章节数、总字符、孤立子节数） | 快速判断篇幅 |

**孤立子节检测**：若某父节只有1个直接子节，子节会被标注 `is_isolated: true`。

**实测（54页论文）**：正确识别10个一级章节（第一～第六章 + 摘要/目录/参考文献/致谢），发现9个孤立子节。

---

### 2.3 `tools/ref_checker_tool.py` — `ref_checker`

**功能**：从 Markdown 全文检查参考文献规范性，对应 `thesis-checklists.md` 的「参考文献检查列表」。

**检查项**：
1. 编号连续性（有无跳号、是否从1开始）
2. 条目格式完整性（年份、条目长度）
3. 正文 `[X]` 引用 vs 文献列表交叉核验（漏引/孤引）

**关键实现细节**：
- 参考文献章节定位：从后向前扫描所有「参考文献」出现，取后方跟有 `[N]` 条目的最后一个（避开目录页中的早期出现）
- 条目解析：支持 `[N] 内容` 同行和 `[N]\n内容` 换行两种格式（学位论文常用后者）
- 正文引用解析：支持 `[1]`、`[1,2]`、`[1-3]` 等格式

**实测**：34 条文献全部识别，34 个正文引用全部匹配；发现 10 条年份缺失（英文会议文献格式问题）。

---

### 2.4 `tools/figure_ref_checker_tool.py` — `figure_ref_checker`

**功能**：检查图/表/算法/公式的交叉引用完整性和编号连续性。

**支持编号格式**：
- 简单格式：`图 1`、`表 2`、`Algorithm 3`
- 章-序号格式：`图 4-1`、`表 5-3`（学位论文常见，各章内部分别检查连续性）

**Caption 识别**：
- 支持行内 caption：`图 4-1 说明文字...`
- 支持 PyMuPDF 将短标签解析为 Markdown 标题的情况：`### 图-1`、`## 表5-3`

**交叉核验**：
- 定义了但正文未引用 → 报告
- 正文引用了但无对应定义 → 报告
- 参考文献章节排除在外（避免文献标题中的图号被误识别为正文引用）

**实测**：找到图4/表9/算法4/公式0，仅1条漏报（公式编号被 OCR 分割导致无法识别）。

## 四、其他开发者须知

### ⚠️ 使用新工具的注意事项

1. **`pymupdf_parse` 仅适用于有文字层的 PDF**（非扫描件）。扫描件仍需 `docling_parse`。

2. **`pymupdf_parse` 标题识别是启发式的**，可能存在误识别：
   - 图表 caption 短文本（如「图4-1」）可能被识别为章节标题
   - 算法伪代码的关键字可能被识别为标题
   - 如遇问题，可调整 `pymupdf_parse_tool.py` 中的 `_classify_label()` 函数

3. **`ref_checker` 要求文献使用 `[N]` 格式**。脚注引用（`①`、`*`）或作者-年份格式（APA）暂不支持。

4. **`figure_ref_checker` 的 caption 检测依赖文本层**。如果图表标题是图片内嵌文字（扫描 PDF），则无法识别，会误报「引用了但无定义」。

5. **`chapter_index` 的层级依赖 `pymupdf_parse` 的标题识别精度**。如果 MD 标题层级混乱，建议先人工检查生成的 MD 文件，再运行 `chapter_index`。

### ⚠️ Checklist Workflow 的 OCR 噪音说明

Docling OCR 会在中文字符之间引入额外空格，并将部分汉字替换为 Kangxi 部首字符（如 `⼿`→`手`、`⼈`→`人`）。`utils/text_normalize.py` 已有对应处理，但 LLM 仍可能把这些 OCR 伪影识别为「作者排版问题」。

**如果你在 checker 的 `system_prompt` 中没有显式说明 OCR 噪音白名单，LLM 很可能把这些伪影报告为排版错误**。参考 `workflow_checklist_annotate_v3.json` 中各 checker 的写法。
