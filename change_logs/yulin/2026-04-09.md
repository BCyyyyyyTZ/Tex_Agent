### 1. 新建文件

#### `config/planner_config.py`
集中存放规划器相关的所有配置常量与共享工具函数，避免参数散落在业务文件中。
- `PLANNER_TEMPERATURE`、`NODE_DEFAULT_TEMPERATURE`、`MAX_PLAN_ROUNDS_DEFAULT`：LLM 温度与迭代轮数
- `NODE_OUTPUT_FORMAT_INSTRUCTION`：统一注入每个专家 Agent system_prompt 末尾的强制 JSON 输出格式
- `COMPLEXITY_AGENT_MAP`、`COMPLEXITY_COMPLEX_KEYWORDS`、`COMPLEXITY_MEDIUM_KEYWORDS`：复杂度推断规则
- `AGENT_TYPE_NAMES`：已知 Agent 类型列表，供 build_dynamic_graph 降级检测使用
- `PLAN_OUTPUT_SCHEMA`、`SUPERVISOR_OUTPUT_SCHEMA`：PlanAgent / Supervisor LLM 输出的 JSON schema 模板
- `parse_llm_json()`：三级容错 JSON 解析工具函数（直接解析 → 提取代码块 → 正则抽取）

### 2. 修改文件

#### `router/planner.py`
在原有抽象类 `MASPlanner` 后追加具体实现类 `AutoAgentsMASPlanner`：

- **规划流程（AutoAgents 思路）**
  - Round 1：PlanAgent LLM 调用，生成初始专家 Agent 列表 + 图拓扑
  - Round 2～N：Supervisor LLM 审查，不通过则用 `revised_agents` 替换方案，直至 `approved=true` 或达到最大轮数

- **图结构约束（在提示词层面强制串行）**
  - PlanAgent 提示词中明确要求：图必须是单链，边数 = 节点数 - 1，禁止并行分支
  - Supervisor 提示词中注入自动检测报告（边数检查 + 并行节点检测），检测到问题必须返回 `approved=false`

- **BaseRouter 预留接口**
  - `assign()` 方法为 BaseRouter 预留接入点
  - 当前阶段：所有节点固定使用 SimpleAgent（其他 Agent 未实现）
  - 未来：注入 BaseRouter 实例后，解注释对应代码即可按复杂度动态选择 Agent 类型

- **其他方法**
  - `validate()`：LLM 对整体执行结果做质量验证
  - `to_graph_config()`：委托 `_translate_plan_to_graph_config()` 翻译，并持久化到 `config/dynamic_workflow.json`
  - `_persist_config()`：将规划结果写入 JSON 文件，供调试复用

#### `workflow/workflow_parser.py`
在原有抽象类 `WorkflowParser` 后追加：

- **`_translate_plan_to_graph_config()`**（独立函数）
  - `TaskPlan` → `(List[NodeConfig], List[EdgeConfig])` 的唯一翻译点
  - 边构建三级策略：`__edges__`（LLM 生成）→ `depends_on` 重建 → 线性链兜底
  - 每级均做连通性验证（BFS），不连通则自动降级，保证所有节点都被执行

- **`YAMLWorkflowParser`**
  - 路径 A（文件）：`load_config()` → `parse_nodes()` → `parse_edges()` → `build_graph()`，支持 JSON / YAML
  - 路径 B（内存）：`from_task_plan(plan)` 直接消费 TaskPlan，无 I/O 开销
  - 两路径最终均汇聚到 `build_dynamic_graph()`

#### `workflow/nodes.py`
追加 `make_generic_agent_node()` 通用节点工厂：
- `system_prompt` / `subtask` / `output_schema` 从 `NodeConfig.config` 动态读取
- 在 system_prompt 末尾统一注入 `NODE_OUTPUT_FORMAT_INSTRUCTION`，强制 LLM 输出结构化 JSON
- 从 `state["metadata"]` 精确读取 `depends_on` 上游节点的 `summary`，注入上下文
- 解析 LLM 输出的 JSON（result / summary / confidence / metadata），存入 `state["metadata"][node_id]`，供下游节点读取

#### `workflow/graph_builder.py`
追加两个函数：
- **`_build_agent_instance()`**：按 agent_type 实例化 Agent，未实现类型自动降级为 SimpleAgent
- **`build_dynamic_graph()`**：根据 `NodeConfig` / `EdgeConfig` 动态构建 LangGraph 图
  - 自动检测入口节点（拓扑源头）
  - 末端节点自动连接 END
  - nodes 为空时回退到硬编码 `build_graph()`

#### `main.py`
新增 `plan`（别名 `mas`）命令：
```
> plan <任务描述>
```
执行链路：AutoAgentsMASPlanner → YAMLWorkflowParser → build_dynamic_graph → app.invoke()

### 3. Bug 修复记录

| 问题 | 原因 | 修复 |
|---|---|---|
| `ImportError: PLANNER_MODEL_DEFAULT` | 删除常量后 import 语句未同步 | 移除对应 import |
| `ValidationError: ChatOpenAI model=None` | `__init__` 传 `model` 而非 `self.model` | 改为 `ChatOpenAI(model=self.model, ...)` |
| `MAX_PLAN_ROUNDS_DEFAULT` 导入未使用 | `__init__` 默认值写死为 `3` | 改为 `max_plan_rounds: int = MAX_PLAN_ROUNDS_DEFAULT` |
| 全部节点选 PlanAndSolveAgent | 关键词过于宽泛，命中率接近 100% | 当前阶段固定使用 SimpleAgent，待其他 Agent 实现后再激活 |
| 只有第一个节点被执行 | LLM 生成边不足导致图不连通 | 连通性 BFS 验证 + 三级降级到线性链 |
| 并行节点触发 `INVALID_CONCURRENT_GRAPH_UPDATE` | LLM 生成了并行分支，两节点同步写 messages | PlanAgent 提示词强制单链约束 + Supervisor 自动检测并行分支 |
| 输出截断 1000 字符 | `display.py` 写死上限 | 移除截断限制 |

### 4. 设计原则

- **最小改动**：只在已有文件末尾追加，不修改原有接口和硬编码逻辑
- **硬编码保底**：`build_dynamic_graph()` 失败时自动回退到原有 `build_graph()`
- **配置集中**：所有可调参数集中于 `config/planner_config.py`，业务文件只 import
- **预留接口**：BaseRouter、工具调用、条件边等预留明确注释，后续按需激活
