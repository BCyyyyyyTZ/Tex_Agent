## 2. 规划与节点输出规范（持续迭代，当前仓库可见部分）

以下条目为 qbb 相关工作在代码中的落点，便于评审与继续深化。

### `router/planner.py`
- **PlanAgent** 与 **Supervisor** 的提示词中增加 **JSON 输出硬约束**：
  - 禁止 Markdown 代码块包裹 JSON
  - 要求首尾为 `{` / `}`
  - 键名双引号、无尾随逗号等
- 目的：降低 `parse_llm_json` 解析失败与“字段修复”频率，提升规划图可执行性。

### `config/planner_config.py`
- **`NODE_OUTPUT_FORMAT_INSTRUCTION`**：由“带 markdown 代码块示例”改为 **纯 JSON 说明 + 合法示例片段**，减少模型模仿 ``` 包裹输出。
- **`PLAN_OUTPUT_SCHEMA` / `SUPERVISOR_OUTPUT_SCHEMA`**：示例由占位符改为 **合法 JSON 字面量**（如 `true`、数字、`[]`），避免模型照抄 `<true 或 false>` 类非法 JSON。

## 3. 挑战型 Workflow（用于检验 agent / tool / user 组合）

### 新增配置（均在 `config/`）
- `workflow_challenge_evidence_choice.json`：证据检索与选择类链路（含上游澄清与检索相关节点设计）。
- `workflow_challenge_risk_gate.json`：风险门控与阶段计划类场景。
- `workflow_challenge_double_user.json`：双用户/多轮人机节点交互场景。

### `config/workflow_registry.json`
- 注册键名示例：`challenge_evidence_choice`、`challenge_risk_gate`、`challenge_double_user`。
- 使用方式：`task` 命令通过 `-wf` 指定上述名称即可加载对应图配置。

### 设计意图（工程向）
- 覆盖 **agent 节点**、**tool 节点**（如 `arxiv_search`）、**user 节点** 的组合与依赖边。
- 部分链路中在 tool 前增加 **query 改写/约束节点**，避免将长段中文全文直接作为检索输入导致 HTTP 414/500 等问题（具体节点 id 以各 json 为准）。
