# yulin 2026/5/31

## 概述

本轮工作将 **Agent 上下文 / Prompt / 画像 / 记忆检索** 从 Python 硬编码迁移到 **可编辑的 JSON 配置**，并引入 **`auto` 单节点对话模式**，同时调整 **Plan / Task** 的默认上下文策略，在尽量不破坏已有 `checklist_*` / `latex_*` / `thesis_*` workflow 的前提下，缓解以下问题：

- Plan / 对话 **答非所问**、复读用户画像、echo 任务被规划成多节点长报告  
- 记忆检索把 **历史问句碎片** 当成当前任务  
- 「你是谁」类短问被 **长篇画像或错误身份** 覆盖  
- 规则散落在多个 `.py` 文件，**改行为必须改代码、难复现**

---

## 一、修改动机（为什么要改）

### 1.1 问题现象

| 现象 | 典型触发 | 根因（归纳） |
|------|----------|--------------|
| 答非所问 | Web 多轮闲聊、Plan 简单任务 | 历史/记忆权重过高；画像块常驻 prompt |
| 复读画像 | 终节点或 Plan 交付 | `user_persona.json` 与「画像已写入」类回复进入上下文 |
| echo 失败 | 「原封不动输出」 | Planner 仍规划多 agent；终节点套用长篇 `FINAL_DELIVERY` |
| 记忆污染 | 「讲 agent 记忆」后追问 | `shared` 检索未过滤 `_prompt_builder` 合成消息 |
| 难调参 | 想关记忆、改关键词 | 逻辑写在 `context_policy.py` / `nodes.py` 的 `if` 与字符串里 |

### 1.2 设计目标

1. **配置驱动**：策略、意图关键词、路由、Prompt 版式集中在 `config/context_config.json`。  
2. **Profile 而非硬编码 workflow 名**：用 `legacy` / `pipeline` / `dialogue` / `auto_single` 描述「上下文怎么组」，而不是在代码里写 `if checklist_*`。  
3. **画像读写分离**：可 **写** `user_persona.json`，但不强制 **读进** 每轮 prompt；画像确认类回复可不写入对话上下文。  
4. **兼容旧 workflow**：`checklist_` / `latex_` / `thesis_` 前缀仍路由到 `legacy`，行为与改前一致。  
5. **入口分流**：Web / CLI 增加 **`auto`**（轻量单轮），`plan` / `task` 使用不同默认 profile。

### 1.3 概念澄清

- **`context_profile`**：上下文组装策略（记忆、metadata 链、prompt 结构、画像开关），**不是**任务分类器。  
- **`user_persona.json`**：长期画像文件；与 `memory_store/shared.jsonl`（共享记忆落盘）不是同一条链路。主路径对话检索不依赖 `shared.jsonl`。  
- **`auto`**：当前实现为 **单节点** `SimpleAgent`；后续可在同配置下扩展为「auto 路由到 plan/task」。

## 二、修改详细内容

### 2.1 新增：统一配置文件

| 文件 | 说明 |
|------|------|
| `config/context_config.json` | **单一配置源**：`routing`、`profiles`、`intent_patterns`、`message_filter`、`planner`、`prompt_templates`、`json_format` 等 |
| `config/context_settings.py` | 加载 JSON、`resolve_graph_context_profile`、`resolve_node_context_behavior`、`match_intent`、`build_agent_prompt`、`filter_messages_for_memory` 等 |

环境变量（可选）：

```bash
# 指向自定义 JSON，相对路径相对于项目根目录
CONTEXT_CONFIG_PATH=config/context_config.json
```

已在 `.env.example` 中补充说明。

### 2.2 `context_config.json` 结构说明

#### （1）`routing` — 图级 profile 解析

解析顺序（**重要**）：

1. 显式 `context_profile`（图/节点）  
2. `workflow_names` 精确匹配（如 `plan_dynamic` → `dialogue`）  
3. `workflow_prefixes` 前缀（`checklist_` / `latex_` / `thesis_` → `legacy`）  
4. `mode_defaults`（`auto` → `auto_single`，`plan` → `dialogue`，`task` → `pipeline`）  
5. `default_profile`（默认 `pipeline`）

> **Bug 修复**：早期实现曾先应用 `mode=task` 再匹配前缀，导致 `checklist_multi_v4` 误用 `pipeline`；已改为 **先 workflow 再 mode**。

#### （2）`profiles` — 四种上下文策略

| Profile | 记忆检索 | 画像写文件 | 画像进 prompt | metadata 链 | Prompt 版式 | 用途 |
|---------|----------|------------|---------------|-------------|-------------|------|
| `legacy` | 开 | 总是 | 总是 | 全开 | `pipeline_legacy` | 原 checklist / latex 等 |
| `pipeline` | 开 | 按意图 | 按意图 | 非终节点开 | `priority_input` | 通用 task |
| `dialogue` | 开 | 按意图 | 按意图 | 关 | `priority_input` | Plan 动态图 |
| `auto_single` | **关**（`mem_limit=0`） | 多意图 | 多意图 | 关 | `chat_compact` | Web 默认 auto |

`auto_single.agent` 内含：`node_id`、`agent_name`、`system_prompt`、`subtask`（**不再写在 `auto_config.py`**）。

#### （3）`intent_patterns` — 意图匹配

支持 `substr` 与 `regex`，用于：画像读写、echo、长篇交付判断、Planner 本地校验等。  
示例意图：`echo`、`persona_write`、`persona_read`、`user_identity`、`assistant_nickname`、`long_form_delivery`。

`persona_intro_merge` 的 `regex` 默认为空，若需「我叫…学生」自动写画像，请在 JSON 中自行补充正则。

#### （4）其它配置块

| 块 | 作用 |
|----|------|
| `persona_reply_skip` | 含「已写入用户画像」等标记的助手回复不进入对话上下文 |
| `message_filter` | 记忆检索时跳过 `_prompt_builder`、过长行等 |
| `terminal_delivery_auto` | 短问自动 `brief` 终节点交付 |
| `planner` | Plan 附加原则、禁止规划的画像工具名、subtask 敏感词 |
| `prompt_templates` | 三种 prompt 拼装布局 |
| `json_format` | `compact` / `full` 输出格式说明 |

### 2.3 重构 / 修改的代码文件

| 文件 | 变更要点 |
|------|----------|
| `context/context_policy.py` | 变薄：re-export `context_settings`，保留旧 import 路径 |
| `context/context_manager.py` | `search` / `build` 使用 `filter_messages_for_memory`；按 profile 过滤 |
| `workflow/nodes.py` | 通过 `resolve_node_context_behavior` + `build_agent_prompt` 组 prompt；画像/记忆/交付由 behavior 驱动 |
| `workflow/graph_builder.py` | 建图时 `resolve_graph_context_profile`；非 legacy 补默认 `include_metadata_chain` |
| `core/agent_cli.py` | 新增 `build_auto_graph_and_app`、`run_auto_task`；Plan 默认 `dialogue` profile |
| `config/auto_config.py` | 仅保留 workflow 标签；agent 文案改从 `profiles.auto_single` 读取 |
| `router/planner.py` | 附加原则与 echo/画像本地校验改读配置 |
| `ui/web/server.py`、`ui/web/static/app.js` | 请求 `mode` 默认 `auto`，流式分支支持 auto |
| `tests/test_context_policy.py` | 配置加载、路由、意图、过滤、Auto 图 compile 等单测 |

### 2.4 运行时数据流（简图）

```
用户输入
  → resolve_graph_context_profile(workflow, mode)
  → resolve_node_context_behavior(node_config, user_input, is_terminal)
  → ContextManager.build / memory.search（按 behavior.mem_limit）
  → build_agent_prompt（按 behavior.prompt_template）
  → Agent.run
  → 终节点按 behavior 决定是否 save 对话、是否跳过画像确认复读
```

### 2.5 刻意未改动的部分

- 各 `config/workflow/workflow_checklist_*.json` 等业务 **subtask / system_prompt** 文案  
- 工具实现与 checklist 流水线节点拓扑  
- `planner_config.py` 中部分终节点交付常量（与 `resolve_final_delivery_addon` 配合，可后续再外置）

## 四、新的使用方法

### 4.1 日常调参：只改 JSON

主文件：`config/context_config.json`。

| 想改什么 | 改哪里 |
|----------|--------|
| Auto 助手人设 | `profiles.auto_single.agent.system_prompt` / `subtask` |
| 「记住我」触发词 | `intent_patterns.persona_write.substr` |
| 新 workflow 用 pipeline | `routing.workflow_prefixes` 或节点 `context_profile` |
| 关闭某 profile 的记忆 | `profiles.<name>.memory_search_enabled` |
| Plan 禁止画像工具 | `planner.forbidden_persona_tool_names` |
| 短问是否长篇交付 | `terminal_delivery_auto` + `profiles.*.terminal_delivery_*` |

### 4.2 CLI

```powershell
# Auto（默认轻量单节点，配置来自 profiles.auto_single）
python main.py auto "你好"

# 裸输入也可走 auto（以实现为准，见 main.py）
python main.py "你好"

# Plan / Task 不变，图级 profile 分别为 dialogue / pipeline（workflow 前缀可覆盖为 legacy）
python main.py plan "帮我规划一个小任务"
python main.py task "..." --wf checklist_multi_v4
```

### 4.3 Web API

- 请求体 `mode`：**默认 `"auto"`**（可选 `"plan"` | `"task"` | `"auto"`）。  
- `auto` 走 `run_auto_task` 单节点图。  
- 前端模式选择与 `app.js` 中 `mode` 字段一致。

### 4.4 节点级覆盖（workflow JSON）

在节点 `config` 中可覆盖图级默认值，例如：

```json
{
  "context_profile": "legacy",
  "persona_read_in_prompt": false,
  "terminal_delivery_style": "brief",
  "mem_limit": 3,
  "include_metadata_chain": true
}
```

无需改 Python 即可做单节点试验。

### 4.5 自定义配置路径

```bash
# .env 或环境变量
CONTEXT_CONFIG_PATH=my_team/context_config.json
```

### 4.6 画像与记忆文件

| 路径 | 说明 |
|------|------|
| `memory_store/user_persona.json` | 长期用户画像；按 `intent_patterns` + profile 策略读写 |
| `memory_store/shared.jsonl` | 共享记忆持久化；**Auto 默认不检索**；若文件仍存在多为其它分支写入 |

## 五、给其他开发者须知

1. **改行为优先改 `context_config.json`**，避免再在 `context_policy.py` 里加关键词列表。  
2. **checklist 稳定性**：依赖 `routing.workflow_prefixes.checklist_` → `legacy`；若新建 workflow 名不以这些前缀开头，会落到 `pipeline`，行为可能变轻。  
3. **路由顺序**：workflow 前缀优先于 `mode`；勿在 `mode_defaults.task` 期望覆盖 checklist。  
4. **`context_policy` 仍可用**：旧代码 `from context.context_policy import match_intent` 等继续有效，实现已转发。  
5. **后续可做**：将 `nodes.py` 中 `profile == "legacy"` 的终节点落盘分支也配置化；`persona_intro_merge` 补 regex；auto 内路由到 plan/task。

## 七、续：冒烟测试与展示修复（2026-05-31 晚）

### 7.1 三种模式 + 模式切换冒烟

脚本：`tests/run_mode_dialogue_smoke.py`  
报告：`output/mode_dialogue_smoke_report.json`

| 步骤 | 模式 | 上下文条数 | 结果 |
|------|------|------------|------|
| auto-1 | auto | →4 | echo `MODE_TEST_A` |
| auto-2 | auto | →8 | 能回忆上一句输出 |
| plan-1/2 | plan | →12 / →22 | SMT 两轮连贯 |
| task-1 | task（default） | →30 | LaTeX 一句介绍 |
| auto-3 | auto | →34 | 跨模式问 SMT → **「有」**（Plan 后上下文保留） |

六步均无 `error`；单元测试 `test_context_policy` + `test_reply_format` 共 **11 passed**。

### 7.2 影评「一句一行」与 `cite turn0search` 垃圾

| 层 | 处理 |
|----|------|
| 后端 | `utils/reply_format.py`：`strip_citation_artifacts`、`normalize_reply_display`；`server.py` 返回前 `_sanitize_reply_text` |
| 前端 | `app.js`：`marked` 使用 `breaks: false`，避免单换行变段落 |
| Prompt | `DELIVERY_FULL_DEFAULT` 增加「勿逐句空行、勿输出检索占位符」 |

**需重启 Web 服务** 后才能在浏览器看到排版修复。

### 7.3 仍须知晓的限制

- **单次 3000 字**：即使用 `full` delivery，单轮 LLM 仍可能不足；长跑文宜用 Plan 多段或专用 Task workflow。  
- **`shared.jsonl`**：历史污染仍可能影响 Plan/dialogue 记忆检索；测试前可清空或换分支。  
- **配置主文件**：运行时以 `config/context_profiles.py` 为唯一数据源；`context_config.json` 已标废弃（可选 `CONTEXT_CONFIG_PATH` 覆盖）。
