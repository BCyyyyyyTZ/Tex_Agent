### 一、目标拆解（PR-10a）

PR-10a 在路线图中包含四个核心点：

1. 引入 `GhostWatchPolicy`（Ghost 专用监视策略）。
2. Ghost 路径默认关闭空闲自动润色（与后续主动润色分离）。
3. 启动即全量诊断，并在目录变更后按 1 秒静默重检。
4. 前端仅在“error 集合变化”时重置卡片状态，避免无新 error 的无效刷新。

本次全部覆盖到代码与测试。

### 二、核心实现设计

### 1) Ghost 策略独立：`latex/ghost_watch_policy.py`

新增 `GhostWatchPolicy`，继承 `WatchService`，并保持接口兼容（后续可继续复用 `ghost_server` 与快照 API）。

关键策略：

- **静默窗口**：`quiet_sec`（默认 1.0s）映射为诊断防抖时间。
- **自动润色开关**：默认 `auto_polish=False`，Ghost 不再自动触发空闲润色。
- **错误签名驱动**：每轮诊断计算 error 签名；若签名未变化，沿用上一轮建议，避免重复调用 LLM 造成 UI 抖动。

### 2) 配置层补齐：`config/settings.py`

新增 Ghost 专用配置项：

- `latex_ghost_quiet_sec`
- `latex_ghost_auto_polish`

并补充 `_env_float` 读取逻辑，保证 `.env` 覆盖行为与现有配置风格一致。

### 3) 服务接入策略：`latex/ghost_server.py` + `latex/ghost_cli.py`

- `ghost_server` 改为默认实例化 `GhostWatchPolicy`（不影响阶段 9 的普通 watch 服务）。
- CLI 新增：
  - `--quiet-sec`
  - `--enable-auto-polish`
- 兼容保留 `--idle-polish-sec`（仅在启用自动润色时生效）。

这样 Ghost 路径与阶段 8 路径形成了“同接口、不同策略”的分层关系，后续演进不互相干扰。

### 4) 前端刷新策略：`ui/ghost/ghost.js`

之前逻辑是：`project_version` 变化就清空卡片忽略态，导致即使没有新的 error，卡片也会被“刷回来”。

本次改为：

- 前端读取 snapshot 的 `error_signature`
- 仅在 `error_signature` 变化时清空忽略态

从交互层面实现“无新 error 不打扰”，对应 PR-10a 的要求。

### 5) 快照契约补充：`watch_events.py` + `watch_service.py`

为支撑 Ghost 前端判断，快照新增：

- `error_signature`
- `error_changed`

并在诊断事件 payload 中携带签名，保证后续 SSE / 轮询都可使用同一判断逻辑。

### 四、PR-10b：纠错卡与应用链路增强

PR-10b 按路线图落地了三条主线：**字段契约扩展、warning 分流、apply 风险修复**。

#### 1) Suggestion 字段扩展与纠错卡契约

- `latex/models.py`：`Suggestion` 新增 `cause_zh`、`advice_zh` 字段。
- `latex/suggestion.py`：解析器支持 `cause_zh/advice_zh`（兼容 `advice` 别名），并在 JSON 解析后写入模型。
- `latex/ghost_watch_policy.py`：新增兜底补全逻辑，保证纠错卡至少具备：
  - 报错信息（`message`）
  - 定位（`issue_id` 对应 issue）
  - 原因（`cause_zh`）
  - 改正方案（`advice_zh`）

这样即使 LLM 输出字段不完整，Ghost 也能稳定显示 10.5 要求的基本结构。

#### 2) warning 与纠错链分离强化（10.4）

- `GhostWatchPolicy` 增加 warning-only 测试，验证 warning 不触发 LLM fix。
- 前端 `ui/ghost/ghost.js` 改为仅在源码区高亮 `severity == error`，warning 默认不在正文行内打标（为后续 10.8 面板保留入口）。

这使用户视图中的纠错信号更聚焦，不会被 warning 干扰。

#### 3) apply 已知缺陷修复（10.9 应用部分）

`latex/apply_edit.py` 增强为“严格位置 + 文本清洗”：

- 新增 `SuggestionRangeError`
- `offset_from_position` 改为越界显式报错（不再静默 clamp 到文件末尾）
- replacement 写回前清理 BOM/空字符，降低“前缀乱码”风险

对应效果：

- 如果 LLM 给到超范围行号（如文件仅 162 行却返回 163/999），`/api/apply` 会返回 400，不再把文本错误插到文件尾部。
- 常见 BOM 导致的异常前缀被过滤。

### 八、PR-10c：对比模式与行内高亮闭环（本轮已实现）

本轮继续按路线图推进 PR-10c，完成了“后端 compare + 前端 compare 按钮 + 操作后清理”的闭环。

#### 1) 新增 compare 写回实现

- 新增 `latex/apply_compare.py`：
  - `apply_suggestion_compare_to_file(...)`
  - 将 `range` 对应原文转换为注释块（`% [TeX_Agent][compare] ...`）
  - 紧随其后插入 `replacement` 正文

该模式用于保留原文证据并快速比较新旧文本，不直接删除旧内容。

#### 2) Ghost API 扩展 compare 模式

- `latex/ghost_server.py` 中 `POST /api/apply` 新增 `mode` 参数：
  - `replace`（默认）
  - `compare`
- `mode=compare` 时调用 `apply_suggestion_compare_to_file`，响应里返回当前 mode。

#### 3) Ghost 前端交互更新

- `ui/ghost/ghost.js`
  - 卡片新增“对比”按钮
  - “应用”调用 `mode=replace`，“对比”调用 `mode=compare`
  - 维护基于活跃纠错卡的建议范围高亮集合
  - 在 `应用/对比/忽略` 后即时清除对应卡片与行内高亮（不等待下一轮轮询）
- `ui/ghost/ghost.css`
  - 新增 `mark.suggestion-error` 样式，突出建议目标范围

这部分满足 PR-10c 的核心交互要求：卡片操作后，视觉上不再残留“待处理”状态。

### 九、PR-10d：主动润色对话框与 API（本轮已实现）

PR-10d 的目标是把润色从“自动触发”切为“用户主动触发”，并在 Ghost 页面内完成闭环。本轮已实现后端、前端、测试三部分。

#### 1) 后端：新增主动润色 API

- 新增 `latex/ghost_polish_prompt.py`，用于组装 Ghost 场景的润色 prompt：
  - 输入：`query`、`target_file`、`target_text`、`context_file`、`context_text`
  - 约束模型返回 JSON：`original_text`、`polished_text`、`problem_zh`、`advice_zh`
- `latex/ghost_server.py` 新增 `POST /api/ghost/polish`：
  - 请求：`{ query, target_file, context_file }`
  - 读取目标文件全文 + 当前上下文文件全文
  - 调用 `SimpleAgent` 生成润色建议
  - 将结果转换为 `Suggestion(source=llm_polish)` 并写入 `polish_suggestions`
  - 返回结构化 `suggestion`（可被前端直接渲染）

#### 2) 定位与建议模型映射

在 `ghost_server` 中增加了对润色返回的定位逻辑：

- 优先根据 `original_text` 在目标文件中定位文本区间并生成 `range`
- 若定位失败或为空，则回退到 `(0,0)`（不阻塞建议展示）
- `problem_zh` 映射到 `message/rationale_zh/cause_zh`
- `advice_zh` 映射到 `advice_zh`
- `polished_text` 映射到 `replacement`

这样润色建议能复用现有建议卡渲染和 apply/compare 能力。

#### 3) 前端：主动润色对话框与绿色高亮

- `ui/ghost/index.html` 新增“主动润色”面板：
  - 目标文件下拉（从现有文件集合中选择）
  - 润色需求输入框
  - 触发按钮与状态提示
- `ui/ghost/ghost.js`：
  - 接入 `/api/ghost/polish` 调用
  - 使用 `context_file = 当前打开文件` 作为上下文输入
  - 在当前文件中对活跃润色建议范围进行绿色高亮
- `ui/ghost/ghost.css` 新增润色高亮样式：
  - `mark.suggestion-polish`

`tests/test_latex/test_ghost_server.py` 新增主动润色用例：
