## 2026-05-13 ~ 2026-05-14 更新内容

### 一、Checklist 文本审查工作流（v1 / v2）

**功能与效果**

- 在既有 `preflight_inputs` → 加载 checklist / 抽目录 / 六路并行审查 → 合并格式化 → `pdf_comment`（工作流里节点名为 `pdf_annotator`）→ 下载与总结 的主干上，补齐「checklist 按章节切块」与「目录驱动的章节路由」，使各分支 agent 只看到与本章相关的审查规则 + 对应正文，降低干扰、便于长 checklist 维护。
- **v1**（`config/workflow/workflow_checklist_text_v1.json`）：参考文献分支仍用 `thesis_outline_extract` 按目录选择器抽取；`references_checker` 为占位节点，固定返回空结果，便于先打通前五章与其它链路。
- **v2**（`config/workflow/workflow_checklist_text_v2.json`）：参考文献分支改为「按路由切子 PDF → Docling → 抽出参考文献 Markdown」，并启用完整的 `references_checker` 子任务（绑定审查包、原 PDF 页码区间、`page_start`/`page_end` 等），使参考文献与其它章节一样可实质审查且页码可与下游批注对齐。

**实现思路**

- 工作流通过 `metadata.*.metadata.tool_metadata` 串联工具输出；并行 fork 后各 extract + checker 分支共享 `checklist_prepare` 产出的 `review_packages` 与 `chapter_routing` 的 `selectors` / `page_ranges`。
- v1 与 v2 的差异集中在 `extract_references` 所用工具名及 `references_checker` 的 `system_prompt` / `subtask` / `depends_on`，其余五章与 join、批注链路保持一致。

**本轮工作流适配（页码区间 + 避免检查项 + 批注入参）**

- 各章节 checker 的 `subtask`：由「代表页 `anchor_page`」改为使用 `chapter_routing.metadata.tool_metadata.page_ranges.<章节>.page_start` / `page_end`（闭区间）；每条审查结果须输出 `page_start`、`page_end`、`text`、`comment`（v2 参考文献使用 `extract_references` 的原 PDF 闭区间）。
- `annotation_formatter`：合并去重键改为 `page_start+page_end+text+comment`；补全缺失页码区间；丢弃与「大模型避免检查的项目」实质相同的问题；配置 **`max_tokens: 65536`**，避免合并几十条意见时 LLM 输出被截断导致下游 JSON 非法。
- `pdf_annotator`：`question_list` 改为 **`${metadata.annotation_formatter.result}`**（不再直连 `join_checkers`），确保传入带页码区间的格式化结果。
- 六个并行 checker 的 `system_prompt` 增加：审查包末尾若含「## 大模型避免检查的项目」，仅属该节的问题不得写入 `result`。

### 二、新增与增强工具

#### 1. `checklist_prepare`（`tools/checklist_prepare_tool.py`）

- **功能**：按 Markdown 二级标题（`## ...`）解析 thesis checklist，确定性拼出六份审查包（abstract / introduction / background_related_work / method / experiment / references），每份 =「通用规则」+「章节组织」+「该章专用列表」；若存在 **`## 大模型避免检查的项目`**，将该节原文附加到**每一份**审查包末尾，并追加固定 **【审查指令】**（不得把该节所列情形作为审查结论写入 `result`）。
- **效果**：审查 agent 输入变短、结构稳定；缺失章节会在 JSON 里列出 `missing_modules` 便于排查模板问题；全分支统一知晓「大模型应忽略的检查项」（如英文与汉字间空格等细粒度排版项）。
- **思路**：正则切分 `##` 段，标题用别名表归一；`metadata` 增加 `avoid_llm_check_section_present`、`avoid_llm_check_section_title`、`module_titles.avoid_llm_check`；参考文献包可通过 `include_reference_rules` 控制是否拼接参考文献专节。

#### 2. `thesis_chapter_route`（`tools/thesis_chapter_route_tool.py`）

- **功能**：读取 `thesis_outline_extract` 产出的 `outline.json`（或内存中的 `tree`），输出六路章节的 `selectors`（供 `thesis_outline_extract` 的 `chapters` 参数）、`representative_pages`（代表页提示）、**`page_ranges`**（各章在原 PDF 上的 1-based 闭区间 `page_start` / `page_end`）、以及 `matched_nodes`（各章匹配到的目录节点明细）。
- **效果**：下游 text 工作流可直接把章节页码区间交给 checker 与 `pdf_comment`，减少「猜页」与 ±N 页盲搜。
- **思路**：由 `matched_nodes` 的 `page_start`、`page_end_exclusive` 汇总为闭区间；`strict=true` 时可在关键路由全空时直接失败。

#### 3. `references_slice_and_docling`（`tools/references_slice_and_docling_tool.py`）

- **功能**：根据 `chapter_routing` 里 references 节点的 `page_start`，并参考其后继章节起点，计算参考文献在原 PDF 中的页范围（1-based，metadata 中同时给出闭区间与 offset）；用 PyMuPDF 切子 PDF，调用现有 `parse_document_to_dir` 做 Docling，再从 Markdown 中截取「参考文献 / References / Bibliography」一节写入 `references_only.md`。
- **效果**：参考文献走「物理页切片 + 专用解析」，比整书 extract 更省 token、版式更贴近参考文献区；metadata 统一使用**原 PDF 页码**，供 v2 中 references_checker 与 PDF 批注对齐。
- **思路**：范围上界取「第一个非参考文献且 `page_start` 大于参考文献起点」的章节，否则一直到文档末尾；支持缓存目录与 `redo_docling` 强制重跑。

工具注册见 `tools/tool_list.py`。

### 三、PDF 批注工具增强（`tools/pdf_comment_tool.py`，工作流节点 `pdf_annotator`，底层工具名 `pdf_comment`）

**功能与效果**

- **页码区间检索（替代原 ±10 页提示页搜索）**：
  - 推荐入参 **`page_start` + `page_end`**（1-based 闭区间）或 **`page_range: [a, b]`**，在区间内按页顺序检索 `text`。
  - 兼容仅 **`page_idx`**（或 `page_start == page_end`）：视为单页；该页未命中时在 **±5 页**内按距离扩展一次。
  - **显式多页区间**（`page_end > page_start`）**不做** ±5 扩展，节省检索时间。
  - 同一 PDF 页的 `get_text("words")` 结果按页缓存，多批注共享同一页时不重复解析。
- **批注正文精简**：页边 FreeText 仅保留 `comment`（违背哪条 checklist + 建议）；去掉序号、`[提示页第 N 页未命中…]`、±N 页搜索说明等调试话术。
- **未命中原文（旁路）**：在区间起始页页边汇总为 `comment` + `针对摘录：…`（过长摘录截断），不再写「已搜±10页」等。
- **相似度模糊匹配**（保留）：子串窗口未命中时，`difflib.SequenceMatcher` 默认 `ratio ≥ 0.9` 接受高亮；多候选片段、去 Markdown 噪声等策略不变。
- **解析失败提示**：当 `question_list` 为超长非法 JSON 时，错误信息提示常见原因为上游 `annotation_formatter` 输出被 **max_tokens 截断**。

**实现思路**

- `_parse_page_span_from_item` 统一解析 `page_start`/`page_end`、`page_range`、`page_idx`。
- 先搜主区间页列表，单页失败再 `_neighbor_pages_excluding_center(±5)`。
- multi 工作流（`workflow_checklist_multi_v4.json`）仍可使用精准 `page_idx`（单页 + ±5 兜底）；`annotation_formatter` 的 `subtask` 已说明勿在 `comment` 中写页码匹配调试信息。

### 四、LLM 输出长度与批注链路修复

**现象**

- `pdf_annotator` 报 `question_list 为空或格式非法`；`offer_download` 因 `pdf_annotator` 未写出 `tool_metadata.output_path` 而缺少 `file_path`。
- 根因：`annotation_formatter` 合并数十条批注后，`result` 为嵌套转义的超长 JSON 字符串；原先 `LlmClient` **硬编码 `max_tokens=4096`**，响应在 JSON 中间截断，整段无法被 `pdf_comment` 解析。

**修改**

| 文件 | 改动 |
|------|------|
| `agents/base_agent.py` | `LlmClient` / `GeminiClient` 支持可配置 `max_tokens`（默认 `settings.llm_max_tokens`）；`set_llm` / `set_gemini` 增加可选参数。 |
| `agents/simple_agent.py` | 构造函数增加 `max_tokens`，传入后端客户端。 |
| `workflow/graph_builder.py` | 从节点 `config.max_tokens` 传入 `SimpleAgent`。 |
| `config/settings.py` | 默认 `llm_max_tokens` **2048 → 8192**。 |
| `workflow_checklist_text_v1/v2.json` | `annotation_formatter` 配置 **`max_tokens: 65536`**。 |
