## 2026-05-13 ~ 2026-05-14 更新内容

### 一、Checklist 文本审查工作流（v1 / v2）

**功能与效果**

- 在既有 `preflight_inputs` → 加载 checklist / 抽目录 / 六路并行审查 → 合并格式化 → `pdf_comment`（工作流里节点名为 `pdf_annotator`）→ 下载与总结 的主干上，补齐「checklist 按章节切块」与「目录驱动的章节路由」，使各分支 agent 只看到与本章相关的审查规则 + 对应正文，降低干扰、便于长 checklist 维护。
- **v1**（`config/workflow/workflow_checklist_text_v1.json`）：参考文献分支仍用 `thesis_outline_extract` 按目录选择器抽取；`references_checker` 为占位节点，固定返回空结果，便于先打通前五章与其它链路。
- **v2**（`config/workflow/workflow_checklist_text_v2.json`）：参考文献分支改为「按路由切子 PDF → Docling → 抽出参考文献 Markdown」，并启用完整的 `references_checker` 子任务（绑定审查包、原 PDF 页码区间、`page_idx` 与兜底代表页等），使参考文献与其它章节一样可实质审查且页码可与下游批注对齐。

**实现思路**

- 工作流通过 `metadata.*.metadata.tool_metadata` 串联工具输出；并行 fork 后各 extract + checker 分支共享 `checklist_prepare` 产出的 `review_packages` 与 `chapter_routing` 的 `selectors` / `representative_pages`。
- v1 与 v2 的差异集中在 `extract_references` 所用工具名及 `references_checker` 的 `system_prompt` / `subtask` / `depends_on`，其余五章与 join、批注链路保持一致。

### 二、新增工具

#### 1. `checklist_prepare`（`tools/checklist_prepare_tool.py`）

- **功能**：按 Markdown 二级标题（`## ...`）解析 thesis checklist，确定性拼出六份审查包（abstract / introduction / background_related_work / method / experiment / references），每份 =「通用规则」+「章节组织」+「该章专用列表」。
- **效果**：审查 agent 输入变短、结构稳定；缺失章节会在 JSON 里列出 `missing_modules` 便于排查模板问题。
- **思路**：正则切分 `##` 段，标题用别名表归一（如「绪论检查列表」与「引言检查列表」），再用固定键名输出 `review_packages`；参考文献包可通过 `include_reference_rules` 控制是否拼接参考文献专节。

#### 2. `thesis_chapter_route`（`tools/thesis_chapter_route_tool.py`）

- **功能**：读取 `thesis_outline_extract` 产出的 `outline.json`（或内存中的 `tree`），输出六路章节的 `selectors`（供 `thesis_outline_extract` 的 `chapters` 参数）、`representative_pages`（代表页提示）、以及 `matched_nodes`（各章匹配到的目录节点明细）。
- **效果**：减少手工写章节选择字符串；与后续 slice、批注的页码提示一致。
- **思路**：扁平化目录树，用标题关键词与「正文根章节」顺序启发式区分摘要、绪论、背景/相关、方法区间、实验根节点、参考文献；`strict=true` 时可在关键路由全空时直接失败，便于 CI 或严格模式。

#### 3. `references_slice_and_docling`（`tools/references_slice_and_docling_tool.py`）

- **功能**：根据 `chapter_routing` 里 references 节点的 `page_start`，并参考其后继章节起点，计算参考文献在原 PDF 中的页范围（1-based，metadata 中同时给出闭区间与 offset）；用 PyMuPDF 切子 PDF，调用现有 `parse_document_to_dir` 做 Docling，再从 Markdown 中截取「参考文献 / References / Bibliography」一节写入 `references_only.md`。
- **效果**：参考文献走「物理页切片 + 专用解析」，比整书 extract 更省 token、版式更贴近参考文献区；metadata 统一使用**原 PDF 页码**，供 v2 中 references_checker 与 PDF 批注对齐。
- **思路**：范围上界取「第一个非参考文献且 `page_start` 大于参考文献起点」的章节，否则一直到文档末尾；支持缓存目录与 `redo_docling` 强制重跑。

工具注册见 `tools/tool_list.py`。

### 三、PDF 批注工具增强（`tools/pdf_comment_tool.py`，工作流节点 `pdf_annotator`，底层工具名 `pdf_comment`）

**功能与效果**

- **提示页邻域搜索**：`page_idx` 仅作「提示页」。当该页 `search_for` 与子串窗口未命中时，在 `PAGE_HINT_SEARCH_RADIUS`（当前为 10）页范围内按离提示页距离由近及远逐页搜索；命中后在高亮页写批注，并在批注中说明是否发生了「跨页纠正」，减少 Docling/模型页码与印刷 PDF 不一致导致的漏标。
- **相似度可接受带（分层模糊匹配）**：在滑动窗口子串匹配之后，对较长片段用 `difflib.SequenceMatcher`：先用 `quick_ratio` 与 `max(0, min_ratio - 0.08)` 做快速下界过滤，再对通过候选计算最终 `ratio`，默认 `FUZZY_TEXT_MATCH_MIN_RATIO = 0.9` 才接受高亮，在控制误匹配的前提下提高「模型摘录与 PDF 略有出入」时的命中率。
- **其它已有策略**（与本次目标一致、共同提高命中率）：多候选片段（整句、标点切分、超长取中段）、去 Markdown 噪声后再搜、未命中时在提示页页边汇总说明等。

**实现思路**

- 搜索顺序：规范化文本 → 构造 `final_candidates` → 对 `_page_indices_near_hint` 返回的每一页调用 `_search_text_instances_on_page`（先精确 `search_for`，再 `_fuzzy_search`）。
