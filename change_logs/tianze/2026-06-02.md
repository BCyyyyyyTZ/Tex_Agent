本次完成了「**先有幽灵窗口，再迁入扩展**」的落地版本：不依赖 VS Code 插件，直接启动一个独立的 Ghost 服务，在浏览器中按源码行号展示纠错/润色建议卡片，并支持将建议一键应用到磁盘文件。

---

### 一、目标与重设计背景

在阶段 9（CLI/Web 列表展示）之后，用户对“行间交互式建议”的需求已经明确，但如果直接进入扩展开发，会受 VS Code API、发布流程与宿主差异约束，迭代成本高。

因此本轮采用两步法：

1. **阶段 10（本次完成）**：先实现独立 Ghost UI（浏览器版行间卡片），验证交互与写回契约。
2. **阶段 11（后续）**：把阶段 10 的能力迁入 VS Code/Cursor 扩展。

这样可以在不阻塞用户使用的前提下，先交付可运行能力，再做编辑器内嵌。

---

### 二、实现概览

#### 1) 新增 `latex/apply_edit.py`

职责：把 `Suggestion` 中的 `file + range + replacement` 应用到目标 `.tex` 文件。

- `offset_from_position(text, line, character)`  
  将 0-based 行列位置映射为字符串偏移，用于切片替换。
- `apply_suggestion_to_file(root, suggestion)`  
  解析建议、定位目标文件、替换范围并写回，返回写入路径。

使用意义：Ghost UI、后续扩展都可以复用这套“建议应用”逻辑，避免重复实现。

#### 2) 新增 `latex/ghost_server.py`

职责：提供 Ghost 专用 HTTP 服务，连接 `WatchService` 与前端页面。

核心接口：

- `GET /api/snapshot`：返回当前 `WatchSnapshot`（issues / suggestions / polish_suggestions）
- `GET /api/file?path=...`：读取并返回指定 tex 文件行数组
- `POST /api/apply`：接收 suggestion，调用 `apply_edit` 写回文件
- `GET /` + `/static`：提供 Ghost 页面静态资源

启动函数：

- `run_ghost_server(...)`  
  负责实例化 `WatchService`、启动服务、可选自动打开浏览器。

#### 3) 新增 `latex/ghost_cli.py`

职责：Ghost 模式命令行入口。

典型参数：

- `--root`：LaTeX 项目根目录（必填）
- `--main-tex`：主 tex（可选）
- `--idle-polish-sec`：空闲润色触发时间
- `--host` / `--port`：服务地址（默认 `127.0.0.1:8771`）
- `--no-browser`：不自动打开浏览器

#### 4) 新增 `ui/ghost/` 前端页面

文件：

- `index.html`
- `ghost.css`
- `ghost.js`

交互能力：

- 左侧源码按行显示（含行号、问题高亮）
- 建议卡片按建议行锚定渲染
- 卡片支持拖动、CSS resize 缩放、忽略、应用
- 轮询 snapshot 自动刷新（版本变化时重置忽略状态）

### 四、如何使用（手工验收）

#### 1) 启动 Ghost UI

```bash
python -m latex.ghost_cli --root tests/test_latex/VaLoRA_TMC --main-tex paper.tex
```

默认浏览器地址：

```text
http://127.0.0.1:8771/
```

#### 2) 基本操作流

1. 在 VS Code（或任意编辑器）修改并保存 `.tex`
2. Ghost 页刷新后显示 issues / suggestions / polish_suggestions
3. 在对应行卡片点“应用”，建议写回磁盘
4. watch 检测到改动并重新诊断

#### 3) 典型 API 检查

```bash
curl http://127.0.0.1:8771/api/snapshot
curl "http://127.0.0.1:8771/api/file?path=main.tex"
```

本次新增/增强测试文件：

- `tests/test_latex/test_apply_edit.py`
- `tests/test_latex/test_ghost_server.py`
- `tests/test_latex/test_ghost_cli.py`

覆盖点：

1. **位置映射正确性**：`line/character -> offset`
2. **建议写回正确性**：能替换目标范围并写入磁盘

说明：watch + LLM 的重路径在单测中通过 monkeypatch 降噪，保证测试关注 Ghost API 与应用逻辑本身。
