## 2026-05-25 更新内容

> 对照文档：[TeX_Agent LaTeX 子系统分阶段实现路线图](../../doc/TeX_Agent%20LaTeX%20子系统分阶段实现路线图.md)（阶段 0～7 已标 **已完成**；阶段 8+ 未做）。

本轮在阶段 6（`latex_diagnose_v0`）之上补齐 **L3 LLM 编译修复**：Prompt 组装 → 单轮 `SimpleAgent` → 建议归一化 → 报告输出。`latex_diagnose_v0` **未改动行为**，无 API Key 时仍可只用 v0。

---

### 一、设计要点

| 原则 | 实现方式 |
|------|----------|
| LLM 只在 Agent 节点 | `fix_agent` 为 `SimpleAgent`；`latex_fix_prepare` / `latex_collect_suggestions` 为确定性 Tool |
| 控制 Token | 仅 `severity=error`；每条 issue 使用 `latex_slice` 片段 ±N 行；默认最多 **5** 条（`LATEX_LLM_MAX_ISSUES_PER_RUN`） |
| 跨文件上下文（2.5） | `collect_ref_context_snippets`：issue 附近 `\ref` → 全局 `labels` → 定义文件小片段注入 Prompt |
| 可扩展 | v0/v1 工作流并存；metadata 键 `__latex_suggestions__` 已预留；阶段 8 润色可复用 `suggestion.py` |

### 二、新增 / 修改模块

#### 1. 纯逻辑（`latex/`）

| 模块 | 职责 |
|------|------|
| `prompt_builder.py` | `build_fix_prompt`、`build_project_meta`、`collect_ref_context_snippets` |
| `suggestion.py` | 解析 LLM / Agent 输出为 `Suggestion`（含 `issue_id` 对齐） |
| `fix_batch.py` | 从 issues + slices 选取 error、生成 `fix_batch` 与合并后的 `prompt_bundle` |
| `fix_agent_prompt.py` | Agent 系统提示常量（workflow JSON 内联了等价说明） |

#### 2. Tool

| tool_name | 作用 |
|-----------|------|
| `latex_fix_prepare` | 读 merge / slice / project 输出，产出 `fix_batch`（无 LLM） |
| `latex_collect_suggestions` | 读 `fix_agent` 的 JSON，写入 `__latex_suggestions__` |
| `latex_report`（增强） | 可选 `suggestions_output`；report 增加 `suggestions`、`suggestion_count` |

#### 3. 工作流 `latex_diagnose_v1`

```text
latex_project → chktex → latexmk → latex_merge → latex_slice(error)
  → latex_fix_prepare → fix_agent → latex_collect_suggestions → latex_report
```

- 注册：`config/workflow_registry.json` → `latex_diagnose_v1`
- 配置：`config/workflow/workflow_latex_diagnose_v1.json`
- `workflow/nodes.py`：Tool 返回的 `__latex_suggestions__` 提升到顶层 metadata（与 project / diagnostics 一致）

### 三、如何使用

#### 1. 环境

- **v0**（无 LLM）：与 [2026-05-22.md](./2026-05-22.md) 相同。
- **v1**（L3 修复）：需配置 `OPENAI_API_KEY`（或项目已有的 Gemini 等兼容通道），与主仓其他 `SimpleAgent` 节点一致。

可选环境变量：

| 变量 | 默认 | 说明 |
|------|------|------|
| `LATEX_LLM_MAX_ISSUES_PER_RUN` | 5 | 单次运行最多送 LLM 的 error 条数 |
| `LATEX_SLICE_CONTEXT_LINES` | 10 | 切片上下文行数（与 v0 共用） |

#### 2. CLI 跑诊断 + 修复建议

任务 JSON 至少包含项目根与主文件：

```json
{"root": "tests/fixtures/latex/multifile", "main_tex": "main.tex"}
```

PowerShell 示例：

```powershell
python main.py task --wf latex_diagnose_v1 '{\"root\":\"tests/fixtures/latex/multifile\",\"main_tex\":\"main.tex\"}'
```

路径可用 `/` 或 `\`；复杂仓库请显式传 `main_tex`（与 v0 相同）。

#### 3. 预期终态（`latex_report`）

`state.output` / `metadata.latex_report.result` 为 report JSON，在 v0 字段基础上增加：

- `workflow`: `"latex_diagnose_v1"`
- `suggestions`: `Suggestion` 对象列表（含 `replacement`、`range`、`issue_id`、`rationale_zh`）
- `suggestion_count`: 非负整数

顶层 metadata 另含：

- `__latex_project__`、`__latex_diagnostics__`（与 v0 相同）
- `__latex_suggestions__`：与 report 中 `suggestions` 对齐的数组

**常见情况**

- 无 error 或无可切片 issue：`fix_batch.task_count=0`，`suggestions` 为空，流水线仍成功结束。
- 有 error 但 LLM 未返回合法 `replacement`：`latex_collect_suggestions` 会跳过该条，不抛未捕获异常。

#### 4. 仅要诊断、不要 LLM

继续使用 **`latex_diagnose_v0`**，行为与 2026-05-22 实现一致。

### 七、阶段 8：目录监视与实时诊断/建议服务（后台服务）

本轮新增了阶段 8 的核心后台服务，支持文件系统的实时监视、防抖诊断和空闲润色。

#### 1. 核心功能

- **目录监视**：使用 `watchdog` 监听指定目录下的 `.tex` 和 `.bib` 文件变更。
- **防抖增量诊断**：文件修改后，经过可配置的防抖时间（默认 500ms），自动触发 ChkTeX（及可选的 latexmk）进行增量诊断，并调用 LLM 修复错误。
- **空闲润色**：当用户停止修改文件超过指定时间（默认 2s）后，自动对活跃文件进行语言润色。
- **事件推送**：通过事件回调机制推送 `diagnostics_updated` 和 `polish_suggestions_updated` 状态快照。

#### 2. 如何使用

在代码中实例化并启动 `WatchService`：

```python
from latex.watch_service import WatchService

def on_event(event):
    print(f"Received event: {event.event_type}")
    print(event.payload)

service = WatchService(
    watch_id="my_watch_session",
    root="/path/to/latex/project",
    main_tex="main.tex",
    on_event=on_event
)

# 启动后台监视
service.start()

# 停止监视
# service.stop()
```

#### 3. 新增 / 修改模块

- `latex/watch_service.py`：后台监视服务实现，包含防抖和空闲触发逻辑。
- `latex/watch_events.py`：定义了 `WatchSnapshot` 和 `WatchEvent` 事件模型。
- `latex/polish_prompt.py`：空闲润色的 Prompt 构建逻辑。
- `config/settings.py`：新增了 `LATEX_WATCH_DIAGNOSE_DEBOUNCE_MS` 和 `LATEX_WATCH_IDLE_POLISH_SEC` 等配置项。
- `requirements.txt`：新增 `watchdog>=4.0.0` 依赖。
