## 2026-05-12 更新内容

### `preflight_inputs_tool`：支持更自由的自然语言输入

面向 checklist 审查等工作流，预检工具不再强依赖「固定键名 + 换行格式」的路径写法，用户可以在一段话里混写说明与路径，由规则抽取与 LLM 语义映射共同解析出后续节点需要的 `pdf_path` / `checklist_path` / `output_path` 等槽位。

#### 主要能力

- **工作流静态扫描**：分析当前工作流后续节点对路径类输入的依赖，归纳 `user_required_slots`，并生成带 `required` / `default_strategy` 的 **槽位契约**（`slot_contract`），区分「必须由用户提供」与「可走合理默认值」的项（例如输出 PDF 可按论文名自动生成默认路径）。
- **严格模式 `strict_mode`（默认开启）**：必填槽位仍缺失时，`ToolResult.success=False` 并给出明确错误信息，避免带着空路径继续跑下游节点。
- **LLM 语义抽取**：默认走 **OpenAI 兼容接口**（`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `LLM_MODEL`），按槽位语义从非规格化文本中匹配路径；可选 `llm_provider=gemini` 保留 Gemini 路径。
- **与编排引擎对齐**：工作流里对 dict 形 `tool_input` 会执行 `tool.run(**payload)`，工具侧 `run` 已兼容 **关键字展开**，避免 `unexpected keyword argument 'user_input'` 一类调用错误。
- **上下文合并**：支持 `context_text` 与本轮 `user_input` 合并后再抽取，便于路径只出现在上文时也能被解析。

#### 使用与配置提示

- 工作流 JSON 中可为 `preflight_inputs` 传入 `strict_mode`、`llm_provider`、`llm_model`、`use_llm` 等字段；未显式写 `output_path` 时，在契约允许下可自动补默认输出路径。
- 修改工具代码后需 **重启 Web 服务 / CLI 进程**，否则可能仍加载旧模块。

### 建立 checklist 多路并行审查 **v4** 工作流

新增 `config/workflow/workflow_checklist_multi_v4.json`（并在 `workflow_registry` 中注册为 `checklist_multi_v4`），相对 v1～v3 的主要编排差异：

- **首节点即 `preflight_inputs`**：合并上文路径与内联路径注册（`run_register: true`），**不再单独挂 `register_inputs` 节点**，减少一步配置与用户心智负担。
- 后续仍为 `load_checklist` + `gemini_upload_pdf` → 六路并行 checker → `join` → `annotation_formatter` → `pdf_annotator` → `offer_download` → `final_report` 等链路；下游节点通过 `metadata.preflight_inputs.metadata.tool_metadata.*` 引用已解析的绝对路径。
- 审查类 Agent 节点可配置为使用更完整的历史/元数据链（便于把用户原始诉求与固定审查子任务一并交给模型），具体以当前仓库内 v4 JSON 为准。

### 新增 `thesis_outline_extract`：按目录树定向抽取章节

新增 `tools/thesis_outline_extract_tool.py`，提供两种模式：

- `mode=outline`：仅提取目录树（优先 pypdf，失败自动兜底 pymupdf 的 TOC），输出章节页码区间。
- `mode=extract`：必须显式传入 `chapters`（无默认全文），按目录树定位页码区间后调用 `pdfplumber` 按页提取正文，并输出 Markdown 与 docling 兼容 JSON。

补充了选择器能力：支持 `3.1;3.2-3.4;第4章` 等混合输入，并记录未命中的章节 token，便于用户纠错重试。

### `preflight_inputs_tool` 增强：支持章节槽位抽取

`preflight_inputs` 的槽位体系从“仅路径”扩展为“路径 + 值”双类型：

- 通过静态扫描识别 `chapter_selection` 这类 value 槽位（除了 `pdf_path` 等 path 槽位）。
- 从自然语言中抽取章节表达式（如“第3章到第4章”“3.1-3.3”），规范化后写入 `metadata.tool_metadata.extra_slots.chapter_selection`。
- 严格模式下会把章节槽位纳入必填校验，缺失时直接失败，避免下游工具收到空章节参数。

### 新增示例工作流：`thesis_chapter_extract`

新增 `config/workflow/workflow_thesis_chapter_extract.json` 并注册到 `workflow_registry`，典型链路为：

`preflight_inputs` -> `thesis_outline_extract` -> `final_report`

用于一轮内完成“路径 + 章节号”解析并定向抽取，不再依赖默认全文解析。
