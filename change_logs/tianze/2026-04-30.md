## 2026-04-22 更新内容

### 一、Checklist 多路审查工作流（v1 / v2 / v3）

新增三套基于 **Gemini + PDF** 的 checklist 审查工作流（无 Docling），前置步骤一致：`register_inputs` → 加载 checklist → 将 PDF 交给 Gemini，区别在 **审查如何拆节点**：

| 版本 | 审查方式 | 特点 |
|------|----------|------|
| **v1** | 6 个 `MultiSimpleAgent` **并行** | 六路维度同时跑，总耗时常取决于「最慢的一路」，适合要缩短墙钟时间的场景。 |
| **v2** | 6 个 `MultiSimpleAgent` **串行** | 一路接一路执行，提示词与维度划分可与 v1 对齐，便于对照实验或控制并发。 |
| **v3** | **单个** `MultiSimpleAgent` 一次审完 | 不拆 6 个审查节点、不拆 checklist 执行流；一次调用承担原六路职责，**调用次数少、整体更快**，适合接受单轮长输出的场景。 |

后处理链路统一：审查结果 →（v1/v2 需合并/格式化）→ `pdf_comment` 页边标注 →（可选）下载链接工具 → 最终总结。

**思路**：用「并行 / 串行 / 单节点」三种拓扑，在**同一套输入与输出协议**下权衡延迟、成本与可维护性；v3 用算力换拓扑简单。

---

### 二、`MultiSimpleAgent` 与附件

为 **`MultiSimpleAgent`** 增加 **上传文件 / 附件** 能力（如 Gemini 侧 `File` 引用），使审查节点可以「带着 PDF」提问，而不是只依赖纯文本描述。

**思路**：与 `SimpleAgent` 的附件注入对齐，保证多模态审查节点能稳定引用同一份文档。

---

### 三、输入解析与「只上传一次」：`register_inputs` + `gemini_upload_pdf`

新增两个工具，把工作流前半段 **标准化**：

1. **`register_inputs_tool.py`**  
   - 从用户输入（含 Web UI 注入的 PDF / Checklist 路径等）解析并 **规范化绝对路径**。  
   - 输出 `pdf_abs_path`、`checklist_abs_path`、`output_pdf_abs_path` 等，供后续节点用占位符引用。

2. **`gemini_upload_pdf_tool.py`**  
   - 对 PDF **预上传到 Gemini**，得到可复用的文件引用（如 `gemini_file`）。  
   - 多个审查节点通过 `attachment` 引用 **同一次上传结果**，避免每个 agent 重复上传同一份 PDF。

**思路**：**注册路径 + 单次上传** 拆成独立 tool 节点后，依赖关系清晰，也减少重复 IO 与 API 调用。

---

### 四、生成文件的 Web 下载：`offer_artifact_download`

新增 **`offer_artifact_download_tool.py`**：

- 入参：生成文件的本地绝对路径（例如 `pdf_comment` 的 `output_path`）。  
- 在服务端登记 **短时有效的 token**，返回相对路径链接：`/api/download/artifact?token=...`。  
- Web UI 在 **终局回复** 中合并展示「附件下载」列表，用户点击即可像普通网页一样保存到本机。

**思路**：不直接把服务器任意路径暴露给浏览器，用 **令牌 + 专用下载路由** 做最小暴露面；终局 Markdown 里附带可点击链接，降低「路径复制错、找不到文件」的成本。

---

### 五、PDF 批注「在旁边」与展示修正

- **批注位置与样式**主要在 **`pdf_comment_tool.py`** 中演进：采用 **页边窄条 FreeText**（如 `china-s`），在 **左/右留白** 排版，并做 **与高亮区域不相交、多条批注纵向避让**，避免说明压在正文或高亮上，实现 **批注在侧、原文可对照**。  
- 若曾将「显示异常」与下载工具混在同一轮修改里：**下载链接**由 `offer_artifact_download` + Web 层拼接；**页面上批注长什么样**由 `pdf_comment` 负责，二者职责分离。

**思路**：便签弹窗对部分阅读器中文支持差 → 改为可见 FreeText；再改为 **页边布局** 以兼顾可读性与不挡高亮。
