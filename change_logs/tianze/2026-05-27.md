### 一、设计思路与功能说明

#### 1. 报告人读层扩展 (`latex_report_tool.py`)
原有的 `latex_diagnose` 工作流输出的 JSON 包含了全量的 issues 和 suggestions，对于大项目来说体积非常大，不方便人类直接阅读或在前端展示。
- **新增 `summary` 字段**：统计了 error 和 warning 的总数，以及按来源（chktex, latexmk, parser）的分布。
- **新增 `issues_top_k` 字段**：默认提取所有的 error 和最多前 20 条 warning，作为前端列表展示的默认数据源，避免全量渲染卡顿。

#### 2. CLI 集成 (`latex/watch_cli.py`)
提供了一个独立的命令行入口，让用户可以直接在终端启动目录监视，并以美观的格式查看实时推送的诊断和润色建议。
- **启动命令**：`python -m latex.watch_cli start --root <你的目录> --main_tex <主文件>`
- **人读视图打印**：当文件发生修改并触发事件时，CLI 会拦截 `diagnostics_updated` 和 `polish_suggestions_updated` 事件，将其转化为带有 Emoji 和清晰缩进的终端文本输出（如“📊 诊断摘要”、“⚠️ 问题列表”、“💡 修改建议”等）。
- **JSON 模式**：支持传入 `--json` 参数，供其他脚本或编辑器插件直接消费标准 JSON 事件流。

#### 3. Web-UI API 集成 (`ui/web/server.py`)
在现有的 FastAPI 服务中，新增了 `/api/latex/watch` 系列接口，使得前端页面可以无缝接入 LaTeX 监视能力。
- `POST /api/latex/watch`：传入 `root` 和 `main_tex` 启动后台监视，返回一个唯一的 `watch_id`。
- `GET /api/latex/watch/{watch_id}/snapshot`：供前端轮询获取当前项目的最新快照（包含最新的 issues、纠错 suggestions 和润色 polish_suggestions）。
- `DELETE /api/latex/watch/{watch_id}`：停止监视并清理资源。
- **并发控制**：同一个目录只会启动一个监视实例，如果重复请求会返回 `already_running` 状态。

### 二、如何运行与测试

#### 1. 通过 CLI 启动监视
打开终端，运行以下命令：
```bash
python -m latex.watch_cli start --root tests/fixtures/latex/multifile --main_tex main.tex
```
启动后，尝试修改 `tests/fixtures/latex/multifile` 目录下的 `.tex` 文件并保存：
- **修改后 500ms**：终端会打印出增量诊断的结果（如果有 error 且配置了 LLM，还会输出修复建议）。
- **停笔 2s 后**：终端会打印出对当前活跃文件的润色建议。

#### 2. 通过 API 测试 Web 接口
启动 Web 服务：
```bash
python -m ui.web.server
```
使用 curl 或 Postman 测试接口：
```bash
# 1. 启动监视
curl -X POST http://127.0.0.1:8765/api/latex/watch \
     -H "Content-Type: application/json" \
     -d '{"root": "tests/fixtures/latex/multifile", "main_tex": "main.tex"}'
# 返回: {"watch_id": "xxxx", "status": "started"}

# 2. 获取快照
curl http://127.0.0.1:8765/api/latex/watch/xxxx/snapshot

# 3. 停止监视
curl -X DELETE http://127.0.0.1:8765/api/latex/watch/xxxx
```
