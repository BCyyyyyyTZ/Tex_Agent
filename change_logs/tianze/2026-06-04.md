### 三、Ghost 交互：忽略后更新状态点

**问题**：用户点击「忽略」后，卡片消失但红/绿点与顶部「修改 / 润色」条数未减少。

**做法**（`ui/ghost/ghost.js`）：

- 用 `dismissed` 集合过滤未忽略建议
- `buildPendingIndexes()` 统一计算各文件与全局的待处理纠错/润色数
- 文件选择器标记、全局状态点、`updateStats()` 均基于「未忽略」条目

效果：忽略一条建议后，对应文件红点/绿点与统计数字立即减 1。

### 四、诊断链路（最终策略）：子文件静态 + 启动一次编译 + 手动编译

**背景**：在 `VaLoRA_TMC` 子文件（如 `weijun/Background.tex`）中手动加入 `\notcommand` 时，原先 Ghost 无法报错。根因包括：

- 静态检查只跑 `main_tex` 单文件，子 tex 未进入 ChkTeX
- ChkTeX 本身难以将「未定义命令」标为 error
- 监视默认未跑 latexmk，编译期错误无法进入 issues

**实现（本日最终版本）**：

| 项 | 改动 |
|----|------|
| 静态检查范围 | `WatchService._resolve_chktex_files()`：有 `main_tex` 时用 `iter_main_closure_files` 扫闭包内全部 tex；无 main 时扫项目下全部 tex |
| 静态检查时机 | Ghost 仅在“用户有文件修改且静默 1s”后触发；若用户无修改则不触发 |
| 启动行为 | 启动后不做自动静态检查；仅做一次编译检查（若启用 latexmk） |
| 后续编译检查 | 改为手动触发：前端按钮调用 `POST /api/ghost/compile` |
| 忽略持久化 | 新增 `POST /api/ghost/dismiss`，记录被忽略报错；同一行同一报错不再进入 LLM、不再生成卡片 |
| Ghost 默认 | `run_ghost_server(..., enable_latexmk=True)`；`ghost_cli` 默认开启编译，新增 `--disable-latexmk` 可关闭 |

**使用**：

```bash
python -m latex.ghost_cli --root tests/test_latex/VaLoRA_TMC --main-tex paper.tex
```

仅需静态、不编译时加 `--disable-latexmk`。若需要后续编译检查，点击 Ghost 顶栏“编译检查”按钮。

**已知局限**：latexmk log 解析在 `\input` 子文件上，偶发将行号归到错误 tex（如 Background 行 17 误标 Intro）；编译已能发现错误，文件定位待后续精修。

### 五、幽灵窗口刷新与编译状态提示

为解决“卡片滚动到下方后被无效刷新重置”的体验问题，本轮补充：

- 轮询 `snapshot` 时，只有 `project_version` 或 `compile_running` 变化才触发重绘
- 不再因 `error_signature` 变化自动清空前端忽略态
- 点击“忽略”后先本地即时消卡，再异步调用 `POST /api/ghost/dismiss` 持久化
- 顶部新增“正在进行编译检查”提示条 + spinner，`compile_running=false` 自动隐藏
