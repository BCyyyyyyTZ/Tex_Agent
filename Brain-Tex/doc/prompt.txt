论文协作写作智能体 (TeX_Agent) 核心架构需求
一、 系统核心模块与接口需求 (请根据此构建骨架)
1. 工具与技能模块 (Tools / Skills)
需要定义一个标准的 BaseTool 接口作为基类，保证高度可扩展性。需预留以下能力的接入点：
文献检索：支持 arXiv API 及其他学术库接入。
数据与可视化：支持数据接收、描述性统计分析，并调用 Matplotlib/Seaborn 生成 IEEE/ACM 规范图表。
图像生成：DALL-E / Stable Diffusion API 接入点（流程图、云图等）。
LaTeX 解析器：用于识别语法错误、结构化解析源码以提供连贯优化建议。

2. 知识增强与记忆模块 (RAG & Memory)
多类别向量库接入：预留接口连接检索资料库、专家经验库和用户自定义库。
多分支上下文：设计一种类似 Git Branch 的上下文状态管理数据结构（如 BranchNode, ContextTree）。允许不同 branch 拥有独立和共享的上下文记忆，支持 Agent 的记忆在多个状态间无缝迁移与回退，应对用户频繁更改想法的场景。

3. 智能体模块 (Agents)
请定义一个标准的 BaseAgent 接口，并衍生出以下四个骨架：
SimpleAgent：单次推理，直接调用工具，负责快速响应和基础提示词生成。
ReActAgent：思考-行动循环，用于复杂的逻辑推导与工具链调用（如检索+分析）。
ReflectionAgent：自我修正模式，预留自我评价标准接口，用于 LaTeX 优化与润色。
PlanAndSolveAgent：计划执行模式，用于拆解复杂统计与长流程控制。
特殊需求：所有 Agent 的设计需预留“情感与情绪分析”的钩子 (Hook) 或接口，使其能感知用户情绪并提供陪伴价值。

4. 多智能体工作流与编排 (LangGraph Workflow)
请基于 LangGraph 的核心概念构建调度骨架：
全局状态 (State): 定义清晰的 TypedDict 或 Pydantic Model 作为全局协同状态，确保包含消息历史、当前任务状态以及多分支上下文的指针。
节点定义 (Nodes): 定义工作流的节点包装器 (Node Wrappers)。每个节点需预留出执行特定 Agent（如 AutoGen agent）、执行 Tool 或人工干预 (Human-in-the-loop) 的接口。
工作流与边 (Workflow & Edges): 提供构建 StateGraph 的骨架代码。预留 add_node 和建立边 (add_edge / add_conditional_edges) 的逻辑架构，用于定义大框架的 Plan-Solve 流程或 Agent 间的接力。

5. 协同、通信与控制模块 (Controller / Router / Comm)
自适应路由 (Router)：基于模型/Agent 能力、任务难易度、用户偏好进行动态任务分配的路由模块接口。
主控引擎 (MAS Planner)：管理 Agent 间的信息共享、任务分解与结果验证。
通信协议 (Communication)：定义多 Agent 架构协同通信的标准消息载体（Message Protocol）。

6. 安全与权限模块 (Security)
预留权限控制与数据保护的拦截器/中间件接口，确保用户文档与隐私信息的安全。
